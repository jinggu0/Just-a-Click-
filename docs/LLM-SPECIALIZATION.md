# Just a Click! LLM 지역화·개량 실행 계획

- 기준 모델: **Qwen3-8B / 공식 Q5_K_M GGUF**
- 상태: 개량 계획 확정, 짧은 합성 입력의 CPU·Vulkan 기준선 측정 완료. 파이프라인 특화·학습·장문 검증 전
- 목표: 한국어 장문 요약의 정확성·근거·스타일 준수를 강화하면서 최대 4시간 전사문의 요약을 요청 후 120초 안에 저장
- 모델과 파일 식별: [결정 0004](decisions/0004-llm-selection.md)

## 1. 지역화 범위

범용 LLM을 새로운 모델로 처음부터 학습하지 않는다. 검증된 원본을 기반으로 제품에 불필요한 실행 요소를 제외하고, 자료를 처리하는 방식과 출력 계약을 정리한 뒤 필요한 부분을 지도 미세조정한다.

| 요소 | 결정 | 구현 방법 |
| --- | --- | --- |
| 범용 대화·자율 에이전트 | 제외 | 대화 UI, 임의 도구 목록, 반복 도구 실행기를 배포하지 않음 |
| 셸·코드 실행 | 제외 | LLM 결과를 실행 코드로 해석하지 않음. 설명용 코드 블록 생성은 유지 |
| 클라우드 AI·원격 추론 | 제외 | 외부 추론 클라이언트와 API 키 요구 제거 |
| 장황한 사고 과정 출력 | 비활성 | non-thinking 템플릿 사용, 실제 출력 확인. 모델 레이어 삭제와 다름 |
| 범용 번역·창작 기능 | 제품 진입점 제외 | 해당 기능의 전용 UI·프롬프트 미제공. 언어 능력 자체는 유지 |
| 한국어·영어 혼용 및 전문 용어 | 강화 | 원문·자료 용어 사전, 오인식 사례, 원어 병기 학습 |
| 장문·정정·결정 사항 추적 | 강화 | 구간 사실 원장과 시간·출처 식별자, 정정 사례 학습 |
| 상위·하위 분류 규칙 | 강화 | 앱에서 상속을 계산하고 모델에는 확정된 규칙 전달 |
| 자료·검색·Notion | 유지·분리 | 앱의 선택적 모듈로 실행, 모델이 사용자 권한을 변경하지 못함 |
| 이미지 생성 | 별도 선택 모듈 | 텍스트 요약 모델에 이미지 생성 역할을 부여하지 않음 |

모델의 수학·언어·코드 지식은 서로 얽혀 있으므로 ‘불필요한 지식만 삭제’한다고 약속하지 않는다. 레이어·헤드 삭제, 어휘 축소, 임의 가지치기는 v1에서 시행하지 않는다. 한국어 이해와 전공 설명이 손상될 위험에 비해 확인된 이익이 없기 때문이다. 실행 도구 제거는 설치·공격 표면·의존성 감소이며, 추론 속도 향상은 별도로 측정한다.

텍스트 모델이므로 스캔 문서·도표의 시각 의미를 직접 이해한다고 가정하지 않는다. PDF/PPTX 추출·OCR 결과와 페이지 메타데이터를 입력하고, 해석할 수 없는 도표는 캡처와 확인 필요 표시로 보존한다. 추후 시각 모델 추가는 별도 범위다.

## 2. 단계 A — 기준선 확보

1. 고정된 Q5_K_M 파일을 다운로드·해시 검증하고 정확한 llama.cpp 빌드와 채팅 템플릿을 기록한다.
2. CPU 실행으로 입력·출력 검증 후 Arc 140V에서 Vulkan과 SYCL을 비교한다. 드라이버와 장치 인식 결과를 남긴다.
3. 짧은 한국어 전사문부터 10분·1시간·4시간의 실제 전사문으로 확대한다.
4. 모델 로딩, 입력 처리, 생성, 저장 시간 및 전체 메모리를 따로 기록한다.
5. Q4_K_M은 Q5_K_M 대비 평가용으로만 비교한다. 기본 모델을 조용히 바꾸지 않는다.

산출물: 재현 가능한 실행 설정, 기준 요약 결과, 품질·성능 표. [첫 실행 보고서](validation/2026-09-17-llm-smoke.md)에 짧은 합성 입력 결과를 기록했다. 실제 10분·1시간·4시간 입력과 Q4 비교는 미실시다.

## 3. 단계 B — 학습 전 파이프라인 특화

### 입력 계약

전사 구간마다 `segment_id`, 시작·종료 시간, 원본 텍스트, 수정본 버전을 부여한다. 자료는 파일·페이지·추출 구간 ID를 갖는다. 입력에 섞인 지시문을 제품 설정으로 승격하지 않는다.

분류 상속과 검색·이미지 옵션의 의존성은 앱 코드에서 처리한다. 충돌을 모델의 판단에 맡기지 않는다. LLM에 전달하는 것은 이미 확정된 필수 섹션·스타일·허용 기능이다.

### 요약 계약

내부 결과는 `title`, `sections`, `claims`, `source_refs`, `uncertainties`, `corrections`, `excluded_segments`로 구성한다. 각 사실은 근거 구간을 참조한다. 회의의 담당자·기한은 명시된 경우에만 채우고 미언급 값은 null로 둔다.

앱은 JSON 구조, 존재하는 출처 ID, 필수 섹션을 결정적으로 검사한다. 출처 ID가 존재한다는 것만으로 주장의 의미가 근거와 일치한다고 판단하지 않는다. 의미 충실성은 별도 평가한다. 형식 오류는 제한된 복구를 적용하며 추가 추론 시간도 120초 측정에 포함한다.

### 장문 처리

- 실제 토큰 수에 따라 분할하고 원문 구간 전체를 처리 대상으로 유지한다.
- 각 구간에서 핵심 사실·예제·정정·미결 사항과 출처를 압축한 사실 원장을 만든다.
- 원장을 병합하여 중복과 후속 정정을 처리하고 최종 분류 양식으로 생성한다.
- 모든 입력 구간이 원장 또는 명시적 제외 기록에 대응하는지 검사한다. 단순 ID 포함으로 정보 보존을 증명했다고 보지 않는다.
- 길이 제한에 도달하면 결과를 완성본으로 표시하지 않는다. 연속 생성·재분할을 수행하고 시간 초과는 실패로 기록한다.

120초 달성을 위해 요약 전에 몰래 모델을 돌려 작업 시간을 숨기지 않는다. 전사 중 사전 요약은 현 기준선에 포함하지 않는다.

## 4. 단계 C — 학습 데이터 구축

첫 데이터셋 목표는 **검수된 1,200개 작업 예시**다. 이는 구축 목표이며 확보된 데이터 수가 아니다.

| 과제 | 목표 수 | 핵심 학습 내용 |
| --- | --- | --- |
| 강의 요약 | 300 | 개념·예제·복습, 한영 용어와 코드 설명 |
| 회의 요약 | 250 | 결정·담당·기한·미결, 취소와 정정 |
| 세미나 요약 | 150 | 주장·근거·시사점·질의응답 |
| 자료 연결 | 200 | 전사와 자료의 일치·충돌·출처, 보강 표시 |
| 규칙·실패 사례 | 300 | 상위 우선, 미언급 정보, 잡담 필터링, 입력 지시문 무시 |

데이터는 작성자 소유, 명시적 허용 또는 적합한 공개 라이선스 자료로만 구성한다. 외부 유료 교사 모델을 호출하지 않는다. 로컬 모델로 초안을 만들 수 있으나 사람이 검수한 정답만 사용한다. 원본부터 평가 정답까지 외부 업로드를 기본 금지한다.

녹음·강의·화자·원본 문서 그룹 단위로 train 80%, validation 10%, test 10%를 분리한다. 같은 녹음의 인접 구간이나 표현만 바꾼 예시가 서로 다른 분할에 들어가지 않게 한다. 장문 사례는 하나의 컨텍스트에 억지로 넣지 않고 구간 사실 추출과 원장 통합 과제로 구성한다.

데이터 레코드에는 `example_id`, `source_group`, `task`, `transcript`, `materials`, `effective_rules`, `options`, `target`, `license`, `review_status`, `split`을 둔다. 테스트셋은 튜닝 중 프롬프트 선택에 사용하지 않고 최종 판정에 사용한다.

## 5. 단계 D — LoRA 지도 미세조정

학습은 GGUF 파일을 직접 수정하지 않고 고정된 원본 `Qwen/Qwen3-8B`에 **LoRA SFT**를 적용한다. LoRA는 기존 가중치에 작은 학습 가능한 행렬을 추가하는 방식이며 학습 대상 수를 줄이지만 실제 학습 메모리·속도는 환경에 따라 다르다. [PEFT 공식 LoRA 문서](https://huggingface.co/docs/peft/developer_guides/lora).

첫 실험 설정은 다음으로 고정하고 검증셋 결과에 따라 한 번에 한 요소씩 변경한다.

- 목표 모듈: attention의 `q_proj`, `k_proj`, `v_proj`, `o_proj`.
- rank 16, alpha 32, dropout 0.05.
- 학습률 0.0001, 최대 2 epoch, 유효 batch 16.
- 시작 sequence length 4,096, microbatch 1, gradient accumulation 16.
- assistant의 목표 출력에만 loss 적용, 입력·패딩 마스킹, seed 42.
- validation의 사실 오류·필수 규칙 위반이 악화되면 이전 체크포인트를 선택한다. 학습 loss 감소만으로 성공 처리하지 않는다.
- attention LoRA로 목표를 충족하지 못하면 MLP 모듈 확대를 별도 실험한다. 초기부터 전체 파라미터 학습을 하지 않는다.

이 값은 실험 설계이며 성능이 입증된 최적값이 아니다. 한 번의 짧은 학습·저장·재로딩 시험으로 학습 실행 환경부터 확인한다. 현재 Arc 140V 노트북에서 8B LoRA/QLoRA가 실용적으로 돌아간다고 가정하지 않는다. QLoRA는 지원 백엔드와 라이브러리가 실제 동작할 때만 선택한다.

이미 사용할 권한이 있는 로컬 또는 자체 보유 GPU에서 학습한다. 무료 크레딧·유료 서버·유료 API에 의존하지 않는다. 적합한 학습 자원이 없으면 데이터·프롬프트·런타임 최적화까지 진행하고 가중치 학습은 미완료로 남긴다. 학습 없이 ‘자체 튜닝 모델 완성’이라고 표시하지 않는다.

학습 후 원본 정밀도에서 adapter를 병합하고 GGUF 변환·Q5_K_M 양자화를 수행한다. 병합 전후, 변환 전후, 양자화 전후를 각각 평가한다. 토크나이저·채팅 템플릿·라이선스·학습 데이터 버전·변환 도구 버전을 함께 기록한다. 새 파일은 새 모델 ID와 해시로 배포하며 원본 manifest를 덮어쓰지 않는다.

## 6. 단계 E — 품질·속도 공동 판정

프로젝트 내부 출시 기준으로 다음을 사용한다. 실제 달성 여부는 아직 확인하지 않았다.

| 지표 | 판정 기준 |
| --- | --- |
| 주요 사실 재현율 | 검수자가 미리 표시한 중요 사실의 95% 이상, 각 강의·회의·세미나 집계별 충족 |
| 중대한 사실 창작 | 평가셋에서 근거 없는 결정·담당자·일정·수치 추가 0건 |
| 근거 충실성 | 검수한 사실 단위 주장 중 98% 이상이 연결된 근거로 뒷받침됨 |
| 출력·상속·옵션 규칙 | 결정적 규칙 검사 사례 100% 통과 |
| 정정·취소 보존 | 전용 평가 사례에서 최종 상태 오류 0건 |
| 사람이 평가한 사용성 | 정확성·가독성·복습/실무 활용성 각 평균 4/5 이상 |
| 시간 | 최대 4시간 입력의 요약 요청부터 저장까지 120초 이하. 최초·반복 실행 구분, 시험 실행별 판정 |
| 개량 효과 | 기존 기준 모델 대비 품질 회귀 없음 및 목표 오류 범주의 개선 확인 |

평가셋에서 0건이라는 결과를 모든 사용자 입력에서 오류가 없다는 보장으로 표현하지 않는다. 시간과 품질 중 하나라도 실패하면 출시 합격으로 처리하지 않는다. 사람이 비교할 때 모델 이름을 가려 평가하고 의견이 엇갈린 사실은 원문으로 재검수한다.

## 7. 120초 목표의 병목 관리

전체 시간은 모델 로딩 + 입력 토큰 처리 + 구간 출력 생성 + 통합 입력/출력 + 검증·저장이다. 4시간이라는 음성 길이만으로 입력 토큰 수를 확정할 수 없으므로 실제 전사문을 토큰화한다.

예를 들어 실제 측정 입력이 40,000토큰이고 생성해야 할 구간·최종 출력 합계가 3,000토큰이라면, 각각 처리량을 `P`, `D`로 두어 `40,000/P + 3,000/D + 기타 시간 ≤ 120초`인지 검토한다. 이 수치는 계산 예시이며 현재 기기의 측정값이나 허용 출력 제한이 아니다.

최적화 순서는 다음과 같다.

1. 실제 병목부터 측정하고 GPU offload·batch·스레드 수를 조정한다.
2. 동일 규칙 프롬프트와 불필요한 중간 출력의 중복을 줄인다. 사실·출처는 보존한다.
3. 필요한 컨텍스트만 할당하고 메모리 압박·스와핑을 확인한다.
4. 학습으로 출력 구조의 반복 실패와 재시도를 줄인다. LoRA 자체가 토큰당 추론을 빠르게 한다고 가정하지 않는다.
5. Q4_K_M은 품질 기준을 모두 충족하면서 유의미한 이점이 있을 때만 새 결정으로 채택한다.

증류·가지치기·작은 모델로의 전환은 v1 개량 기본 계획에서 제외한다. 현재 선택으로 목표를 충족할 수 없다는 근거가 생겼을 때 후속 결정으로 검토한다. 미충족을 숨기거나 120초에 미완성 요약을 완료로 표시하지 않는다.

## 8. 완료 산출물

- 기준 모델·런타임 manifest와 파일 무결성 기록.
