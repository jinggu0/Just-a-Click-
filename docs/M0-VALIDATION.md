# M0 로컬 AI 기술 검증 계획

- 상태: 모델 무결성 확인과 CPU·Vulkan 합성 회의문 각 3회 실행 완료. STT·장문·출시 품질 검증은 미완료
- 기준 기기: [환경 기록](decisions/0001-target-environment.md)
- 기준 LLM: [Qwen3-8B Q5_K_M 선정 기록](decisions/0004-llm-selection.md). STT는 [기존 후보 기록](decisions/0002-runtime-candidates.md) 참조

## 1. 실행 순서

| 순서 | 작업 | 산출물·통과 조건 |
| --- | --- | --- |
| 1 | 공식 런타임 릴리스·모델 파일 선택 | 버전·revision·파일 해시·라이선스 기록, 비용 없는 로컬 실행 확인 |
| 2 | CLI CPU 실행 확인 | 짧은 한국어 음성의 전사와 해당 전사문의 한국어 요약 성공 |
| 3 | 확정된 8B Q5_K_M 요약과 STT 후보 검증 | 동일 입력·출력 조건의 시간·메모리·품질 기록. Q4는 비교 실험용 |
| 4 | Intel GPU 가속 비교 | 실제 장치 인식과 CPU 대비 성능·정확성 비교, 실패하면 CPU 기준 유지 |
| 5 | 장문 확대 | 10분 → 60분 → 240분 순서로 누락·중복·발열에 따른 시간 변화 확인 |
| 6 | 장애·오프라인 검증 | 원본 보존, 구간 재개, 취소, 네트워크 차단 시 로컬 처리 성공 |
| 7 | 결과로 출시 적합성·미정 스택 결정 | 확정 모델의 실측 근거를 기록하고 미충족 시 변경 결정을 별도 작성 |

개발용 런타임 준비와 최종 Install Manager의 설치 정책은 분리한다. 모델·바이너리는 소스 저장소에 커밋하지 않고 외부 캐시에서 관리한다. 시스템 드라이버 변경은 초기 검증의 전제로 두지 않는다.

## 2. 평가 입력

- 사용 권한이 확인된 한국어 음성과 수동 정답 전사문을 사용한다. 개인 폴더의 녹음을 자동 탐색하거나 가져오지 않는다.
- 초기 사례는 강의·회의·세미나 각 1건 이상, 한국어·영어 혼용 전문 용어, 침묵, 반복 발언, 정정 발언을 포함한다.
- 원문에 담당자·기한이 없는 회의와 이전 발언을 취소하는 사례를 넣어 사실 창작을 평가한다.
- 합성 텍스트는 구조·규칙 검증에 사용할 수 있지만 실제 음성 인식 품질 평가를 대신하지 않는다.
- 반복 연결한 4시간 파일은 안정성 시험으로만 분류한다. 실제 장문 품질은 다양한 내용이 있는 입력으로 따로 평가한다.
- 평가 음성을 준비하지 못하면 해당 항목을 미실시로 기록하며 성능이나 품질을 추정값으로 채우지 않는다.

## 3. 4시간 처리 구조 초안

1. 녹음 중 구간 파일과 저장 완료 위치를 점진적으로 기록한다. 구간 길이는 구현 실험 후 정한다.
2. 전사 작업은 작은 구간으로 실행하며 전체 타임스탬프로 환산한다. 겹침을 사용하면 경계의 중복 제거를 검증한다.
3. 전사문은 실제 토큰 수를 기준으로 분할한다. 프롬프트·규칙·출력 예약분을 컨텍스트 예산에 포함한다.
4. 구간별 핵심 사실과 근거 위치를 저장하고 계층적으로 통합한다. 통합 입력도 예산을 초과하면 다시 나눈다.
5. 정정·취소·결정 사항이 구간을 넘어도 최종 요약에 반영되는지 검수한다.
6. 완료한 구간은 체크포인트로 저장한다. 재실행 시 입력·모델·설정이 같은 구간만 재사용한다.

우선 STT와 LLM을 순차 실행한다. 녹음과 동시에 전사하는 기능은 이번 계획의 필수 범위가 아니다.

## 4. 측정 항목

- 런타임 버전, 모델 revision·양자화, 백엔드, 실제 장치, 컨텍스트, 생성 제한, 프롬프트 버전.
- 입력 길이와 토큰 수, 모델 로딩·전사·구간 요약·통합·전체 소요 시간.
- STT 실시간 계수: 전사 소요 초 / 음성 길이 초. 전체 요약 시간과 구분한다.
- 전체 작업 프로세스 트리의 메모리, GPU 메모리, 임시 파일 최대 크기. 계측 불가 항목은 명시한다.
- 전원 연결 여부와 전원 모드. 첫 실행과 모델 캐시가 있는 실행을 구분한다.
- 전사 문자 오류율 및 지정 전문 용어 정확도. 정규화 규칙을 고정해 원본 측정값도 보관한다.
- 핵심 사실 재현율, 근거 없는 사실 수, 필수 섹션 준수, 상·하위 규칙 충돌 결과.

짧은 비교 시험은 동일 조건으로 3회 실행하고 중앙값과 범위를 기록한다. 4시간 안정성 시험은 우선 1회 수행하고 실패·변경이 있는 경우 추가 실행한다.

## 5. 합격 기준

### 확정된 기능 기준

- 네트워크 없이 실제 전사·요약 완료, 원본 외부 전송 없음.
- 4시간 입력 완료, 취소·실패 후 저장된 원본과 완료 구간 보존.
- 상위 필수 규칙 유지, 사용자 수정본 사용, 출처 타임스탬프 유지.

### 내부 품질 합격 기준

- 검수용 정답에 표시한 핵심 사실의 95% 이상 반영, 분류별 집계 기준.
- 정답에 없는 담당자·기한·결정 사항의 확정적 추가 0건.
- 사실 단위 주장의 근거 충실성 98% 이상. 수치 창작과 정정·취소 오류도 별도 검사.
- 필수 섹션·명시적 우선순위 평가 사례 전체 통과.
- 전문 용어 정확도와 전사 오류율은 기준 모델 측정 후 목표를 정한다.

위 품질 수치는 [지역화 계획](LLM-SPECIALIZATION.md)에서 정한 내부 출시 기준이며 달성 여부는 미검증이다. 사용자 시간 요구는 전사 완료 후 요약 실행 요청부터 최종 로컬 저장까지 최대 120초로 확정되었다. 모델 로딩·분할·통합을 포함하고 전사 시간은 별도로 측정한다. 최대 메모리 합격선은 측정 후 결정한다. 품질과 시간은 각각 판정하며, 속도를 위해 입력을 생략하거나 품질 기준을 낮추지 않는다. 시간 경계는 [설치·성능 결정 기록](decisions/0003-installation-and-performance.md)을 따른다.
