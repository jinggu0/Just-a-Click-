# Just a Click! (딸깍!) 제품 요구사항 정의서

- 문서 버전: v0.7 — 시간 목표 판정 전원 조건 확정
- 작성일: 2026-09-16 (최종 수정 2026-09-17)
- 서비스 영문명: **Just a Click!**
- 서비스 한국어명: **딸깍!**
- 문서 목적: 제품의 원칙, 사용자 경험, 기능 범위, 수용 기준 및 확장 방향 정의
- 상태: 한국어 대학 강의 우선, 녹음 중 미리 처리와 녹음 종료 후 5분 노트 목표, 단계적 출시(A→B→C), Tauri 2 앱 구조 확정. 짧은 합성 입력의 CPU·Vulkan 실행만 확인했으며 목표 시간·장문·출시 품질은 미검증이다.

> 본 서비스는 추후 기능 추가와 변경을 전제로 개발한다. 이 문서의 기능 목록은 최종 범위를 제한하지 않는다. 녹음·전사·요약·자료 처리·외부 연동을 독립적으로 확장할 수 있도록 설계하며, 신규 기능에도 유료 API 미사용과 계정 없는 로컬 저장 원칙을 적용한다.

## 1. 제품 개요

Just a Click!은 본인이 수강하는 한국어 대학 강의를 우선 대상으로 하는 Windows 앱이다. 녹음하는 동안 로컬 음성 인식 모델로 전사하고 로컬 LLM으로 구간별 정리를 진행하여, 녹음이 끝나면 근거가 연결된 강의 노트를 제공한다. 회의·세미나 요약도 분류로 지원한다. 다글로와 Notion AI류의 녹음·정리 경험을 참고하되, 사용자 기기에서의 처리와 저장, 계층적인 요약 스타일 설정, 강의 자료 활용을 제품의 중심에 둔다.

사용자는 서비스 계정을 만들지 않고 이용한다. 요약 결과를 로컬에서 확인·수정·저장·다시 요약할 수 있으며, 원할 경우 자신의 Notion 워크스페이스 내 지정한 페이지에 직접 정리할 수 있다.

### 1.1 사용 범위

- 개발자 본인과 지인·동료 몇 명이 사용한다. 불특정 다수 대상 공개 배포는 현재 범위가 아니며 별도 결정이 필요하다.
- 대상 PC는 Windows 10·11을 사용하는 RAM 16GB 이상 최신 노트북(내장 GPU, Vulkan 지원)이다. RAM 8GB 이하 PC의 동작은 보장하지 않는다.
- 범위 결정의 근거는 [결정 0006](decisions/0006-lecture-first-product-scope.md), 앱 기술은 [결정 0007](decisions/0007-app-stack.md)을 따른다.

### 1.2 해결하려는 문제

- 2~3시간짜리 강의를 다시 듣거나 전사문을 읽으며 정리하는 데 많은 시간이 든다.
- 일반적인 요약만으로는 강의의 개념 설명, 예제, 시험·과제 공지처럼 복습에 필요한 정보를 충족하기 어렵다.
- 전공 용어의 전사 오류와 강의 자료의 누락 때문에 요약의 정확성이 낮아진다.
- 녹음, 강의 자료, 요약 결과, Notion 정리 사이에 반복 작업이 발생한다.
- 구독 및 API 비용과 원본 데이터의 외부 전송이 서비스 사용의 부담이 된다.

### 1.3 주요 사용자와 사용 사례

| 우선순위 | 사용자 | 사용 사례 | 기대 결과 |
| --- | --- | --- | --- |
| 1 | 대학생 | 운영체제·리눅스보안실습 등 2~3시간 한국어 강의를 강의실 마이크나 온라인 강의 소리로 녹음하고 강의 PDF·PPTX를 첨부 | 개념, 예제, 용어, 시험·과제·공지, 실습 명령어가 근거와 함께 정리된 강의 노트 |
| 2 | 실무자·팀원 | 회의를 녹음하고 회의 분류로 요약 | 안건, 결정 사항, 담당자와 후속 작업 정리 |
| 2 | 세미나 참가자 | 발표를 녹음하고 발표 자료를 첨부 | 핵심 주장, 근거, 질의응답과 시사점 정리 |
| 2 | 개인 사용자 | 자체 분류와 스타일을 생성 | 목적에 맞는 반복 가능한 요약 양식 |

우선순위 2의 용도는 분류와 기본 스타일을 제공하되, 품질 검증은 강의 이후에 수행한다.

## 2. 핵심 원칙과 제약

### 2.1 유료 API 미사용 및 유지비 0원 목표

1. 전사, 요약, 이미지 생성, 검색을 포함한 모든 기능은 과금이 필요한 API를 사용하지 않는다.
2. 체험 크레딧, 한시적 무료 사용량, 유료 서비스의 무료 할당량에 핵심 기능을 의존하지 않는다.
3. 기본 기능에 상시 운영 서버, 유료 데이터베이스, 유료 인증 서비스를 요구하지 않는다.
4. 사용자 기기의 연산 자원·저장 공간·전력과 인터넷 연결은 실행 환경으로 본다. ‘유지비 0원’은 서비스 운영자의 필수 인프라 및 API 지출을 0원으로 설계한다는 목표이며, 사용자 기기 비용까지 없다는 의미는 아니다.
5. 외부 연동의 비용·약관·인증 조건은 구현 전에 검증한다. 조건을 충족하지 못하면 해당 기능을 보류하거나 무료 대안을 적용한다.
6. 무료 연동이 실패하거나 중단되어도 로컬 녹음·전사·요약·저장 기능은 계속 사용할 수 있어야 한다.

### 2.2 서비스 계정 없는 로컬 저장

1. 서비스 자체의 회원가입, 로그인, 사용자 계정 서버를 구현하지 않는다.
2. 녹음, 전사문, 첨부 자료, 요약, 사용자 분류와 스타일은 기본적으로 사용자 기기에 저장한다.
3. 여기서 ‘로컬 스토리지’는 로컬 영속 저장 전반을 의미한다. 대용량 음성·문서까지 브라우저의 `localStorage`에 저장하도록 제한하지 않는다. 실행 형태에 따라 로컬 파일, 로컬 DB, IndexedDB 등 적합한 방식을 선택한다.
4. Notion 연결은 선택적인 외부 서비스 연결이다. 사용자가 Notion에서 직접 만든 내부 연결의 토큰을 입력하는 방식으로 제공하며, Notion을 연결하지 않아도 핵심 기능 전체를 사용할 수 있어야 한다.
5. 원본 데이터의 자동 업로드, 원격 동기화, 원격 분석 수집은 기본 범위에 포함하지 않는다.

### 2.3 로컬 AI 및 오프라인 사용

- 음성 인식과 요약 추론은 사용자 기기에서 수행한다.
- 녹음 중에도 로컬 전사와 구간 요약을 미리 수행할 수 있다. 이 처리 시간은 숨기지 않고 녹음 종료 후 처리 시간과 구분해 기록한다.
- 최초 설치 및 모델 다운로드 이후에는 외부 검색과 Notion 연동을 끈 상태에서 핵심 흐름을 오프라인으로 완료할 수 있어야 한다.
- 기기 성능이 부족하더라도 유료 또는 클라우드 AI로 자동 전환하지 않는다. 순차 처리, 처리량 조절, 안내 가능한 실패 상태를 제공한다.
- 한국어 강의와 한국어·영어 혼용 전공 용어를 지원 대상으로 삼는다. 영어로 진행하는 강의는 보류한다.

## 3. 제품 목표와 성공 지표

### 3.1 목표

- 녹음부터 복습 가능한 강의 노트까지 하나의 흐름으로 완료한다.
- 녹음 중 미리 처리하여 녹음이 끝나면 5분 안(목표)에 노트를 제공하고, 이후 더 정밀한 버전으로 보완한다.
- 분류와 세부 분류에 따라 재사용 가능한 요약 스타일을 제공한다.
- 원본에 근거한 요약을 생성하고, 불확실한 내용을 사용자가 확인할 수 있게 한다.
- 강의 자료를 활용하여 설명을 보강하되 녹음 내용과 보강 내용을 구분한다.
- 저장된 강의를 다시 찾고 다른 스타일로 다시 요약할 수 있게 한다.
- 사용자 선택에 따라 결과를 Notion의 원하는 위치에 정리한다.

### 3.2 검증 항목

| 지표 | 측정 방법 | 초기 기준 |
| --- | --- | --- |
| 핵심 흐름 완주 | 녹음 → 녹음 중 전사·구간 초안 → 종료 후 노트 → 로컬 저장 시나리오 | 지원 환경의 필수 시나리오 전부 통과 |
| 오프라인 독립성 | 모델 설치 후 네트워크를 차단한 상태에서 실행 | 핵심 흐름 완료 |
| 외부 통신 통제 | 검색·Notion 비활성 상태의 네트워크 동작 확인 | 원본·전사·요약의 외부 전송 없음 |
| 요약 정확성 | 검수자가 핵심 사실 누락과 근거 없는 사실 추가 평가 | [지역화 계획](LLM-SPECIALIZATION.md)의 내부 출시 기준 |
| 용어 전사 정확도 | 한국어 및 전공 용어 평가셋에서 오류율 측정 | 기준 모델 대비 개선, 수치는 기술 검증 후 확정 |
| 종료 후 노트 시간 | AC 전원·Windows 전원 모드 "최고 성능"의 기준 기기에서 2~3시간(대표)·4시간(최대) 강의의 녹음 종료부터 5분 노트 저장까지 | 5분 이내(목표), 품질 기준 동시 충족 |
| 다시 요약 시간 | 같은 전원 조건에서 저장된 강의를 다른 스타일로 다시 요약 | 1시간 이내(목표), 품질 기준 동시 충족 |
| 녹음 중 처리 | 전사 지연, 녹음 중 처리 시간, 메모리, 배터리 사용 | RAM 16GB 노트북에서의 동시 처리 가능 여부와 한도를 출시 전 확정. 1차 측정은 [보고서](validation/2026-09-23-concurrency.md)와 [결정 0009](decisions/0009-concurrent-processing.md)에 기록했다(추정, 배터리·16GB 실기기 미검증) |
| 규칙 준수 | 상·하위 규칙 충돌 및 출력 형식 시나리오 | 정의된 우선순위와 필수 구조 준수 |
| Notion 전송 신뢰성 | 성공·권한 오류·재시도 시나리오 | 성공 확인 가능, 실패 시 로컬 결과 보존 |

처리 속도와 요약 품질은 검증 없이 보장하지 않는다. 실제 강의 평가셋을 이용해 기준 모델과 개선 결과를 비교한다.

위 단계는 구현 순서다. PDF·PPTX와 Notion 연동은 첫 공유 버전의 필수 요구사항이다. 모델 개량은 프롬프트·처리 방식 개선부터 시작하며, 학습은 평가 결과로 필요성이 확인될 때 수행한다.

## 5. 사용자 흐름과 화면

### 5.1 기본 흐름

1. 첫 실행 시 로컬 저장 위치, 필요한 모델과 다운로드 용량, 기기 요구 조건을 확인한다.
2. 녹음 시작 화면에서 과목(분류·세부 분류)과 강의 자료를 고르고, 입력(마이크 또는 PC 시스템 소리)과 요약 옵션을 확인한다. 최근 선택이 기본값으로 채워진다.
3. 필요한 권한을 허용하고 녹음을 시작한다. 일시정지·재개·종료할 수 있다.
4. 녹음 중 앱이 전사와 구간 초안을 미리 만든다. 사용자는 경과 시간, 입력 상태, 미리 처리 상태를 확인한다.
5. 녹음을 종료하면 남은 구간 처리와 최종 통합이 자동으로 진행되며 진행률(%)과 현재 단계를 표시한다. 5분 노트가 저장되면 알리고, 이어서 백그라운드에서 정밀 정리 버전을 만든다.
6. 노트의 본문, 근거 구간, 자료 출처, 교정 사항, 보강 내용을 검토·수정한다. 전사문을 수정하면 바뀐 구간만 다시 처리하여 새 노트 버전을 만든다.
7. Notion이 연결되어 있으면 대상 페이지를 확인하여 전송한다.
8. 라이브러리에서 지난 강의를 찾아 다시 열거나, 다른 분류·스타일로 다시 요약하거나, 삭제한다.

### 5.2 주요 화면

## 6. 기능 요구사항

### 6.1 녹음 및 로컬 전사

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| REC-01 | 녹음마다 마이크 또는 PC 시스템 소리 중 하나를 선택하여 녹음하고 일시정지·재개·종료 제공 | 권한 허용 후 녹음 가능, 일시정지 구간은 녹음에 포함되지 않음, 온라인 강의 소리 녹음 가능 |

| REC-04 | 녹음 중 절전·대기 전환으로 녹음이 끊기지 않게 처리 | 녹음 중 절전 진입 방지, 중단 발생 시 원인과 복구 상태 표시 |
| REC-05 | 녹음 시작 전에 과목과 강의 자료 선택, 최근 선택 기억, 녹음 허락 안내. 강의 자료 선택은 B 단계부터 제공 | 이전 과목 설정으로 바로 시작 가능, 교수자 방침 확인 안내 표시 |
| STT-01 | 녹음 파일을 로컬 모델로 전사 | 음성 데이터가 외부 AI 서비스로 전송되지 않음 |
| STT-02 | 타임스탬프를 포함한 전사 검토와 수정 | 사용자가 특정 구간을 재생·수정하고 수정본으로 다시 요약 가능 |
| STT-03 | 원본 전사와 사용자 수정본 구분 | 편집 후에도 최초 전사 및 수정 여부 추적 가능 |
| STT-04 | 녹음 중 저장된 구간을 순서대로 전사 | 전사가 녹음을 따라잡지 못하면 LLM 미리 처리를 줄이고, 종료 후 남은 구간을 처리 |

기존 음성 파일 가져오기, 입력 혼합, 화자 분리, 실시간 자막 표시는 확장 후보이며 현재 범위가 아니다.

### 6.2 로컬 LLM 요약

- **SUM-01:** 전사문, 분류 규칙, 세부 분류의 추가 규칙, 선택 자료, 옵션을 입력으로 사용한다.
- **SUM-02:** 녹음 중 약 5분 분량(실제 토큰 기준)마다 구간 초안을 만들고 녹음 종료 후 통합한다. 구간 초안에는 요점, 개념·용어, 예제·코드, 시험·과제·공지 후보와 근거 구간을 담는다. 구간 경계의 내용 누락과 중복을 평가한다.
- **SUM-03:** 원본에 없는 결정 사항, 담당자, 일정, 수치 등을 사실로 만들지 않는다. 근거가 없으면 ‘언급 없음’ 또는 ‘확인 필요’로 표시한다.
- **SUM-04:** 요약 결과는 편집 가능해야 하며, 실패·취소 시 기존 원본과 저장된 결과를 보존한다.
- **SUM-05:** 모델 식별자·버전, 적용한 규칙, 옵션, 입력 버전을 기록해 결과 생성 조건을 확인할 수 있게 한다.
- **SUM-06:** 결과 내 주요 사실은 가능한 경우 전사 구간이나 첨부 자료 페이지와 연결한다. 근거를 찾지 못한 보강 내용은 확정된 원본 사실처럼 표시하지 않는다.
- **SUM-07:** 녹음 종료 후 5분 노트를 먼저 저장하고, 백그라운드에서 전체를 다시 읽는 정밀 정리 버전을 만든다. 정밀 버전은 품질 검사를 통과한 경우에만 기본 보기로 바뀐다. 사용자가 수정한 노트는 자동 교체하지 않고 새 버전으로 알린다. 새 녹음이 시작되면 정밀 정리를 일시정지하고 이후 재개한다.
- **SUM-08:** 전사를 수정하면 바뀐 구간의 초안만 다시 만들고 새 노트 버전을 생성한다. 기존 버전은 보존한다.
- **SUM-09:** 요약 진행 중에는 진행률(%)과 현재 단계를 함께 표시한다. 계산 방식은 9.1을 따른다.

시간 목표는 품질을 우선한다.

- 녹음 종료부터 5분 노트 저장까지 5분 이내. 녹음 중 미리 처리가 정상 동작한 경우에 적용하며, 녹음 중 처리 시간은 따로 기록한다.
- 라이브러리 다시 요약은 요청부터 새 노트 버전 저장까지 1시간 이내.
- 시간 목표는 AC 전원 연결과 Windows 전원 모드 "최고 성능"에서 판정한다. 배터리 사용이나 다른 전원 모드의 결과는 참고로 기록하며, 측정할 때 전원 상태를 함께 남긴다.
- 품질 기준에 못 미친 결과는 시간과 관계없이 완성본으로 저장하지 않으며, 시간 초과는 ‘품질 통과·시간 실패’로 기록한다. 측정 구간의 세부 정의는 [결정 0006](decisions/0006-lecture-first-product-scope.md)을 따른다.

수용 기준: 같은 입력에 대해 모든 문장이 같을 필요는 없지만, 필수 출력 구조와 규칙 우선순위가 유지되어야 한다. 근거 없는 사실 추가, 핵심 사실 누락 및 장문 통합 품질을 별도로 평가하며, 5분 노트와 정밀 버전을 각각 평가한다.

### 6.3 요약 분류와 세부 분류

기본 상위 분류와 스타일은 다음과 같다.

| 분류 | 기본 요약 구조 |
| --- | --- |
| 강의 | 주제, 핵심 개념, 설명·예제, 주요 용어(한국어 설명·영문 원어), 시험·과제·공지, 실습 명령어·코드, 복습 항목 |
| 세미나 | 발표 주제, 핵심 주장, 근거, 시사점, 질의응답 |
| 회의 | 안건, 논의 내용, 결정 사항, 후속 작업, 미결 사항 |
| 일반 | 전체 개요, 주요 내용, 핵심 정리 |

- 복습 질문, 질의응답 등은 사용자가 스타일의 필수 섹션이나 추가 지시로 넣을 수 있다.
- 시험 범위·과제 마감·공지는 원문 발언이 있을 때만 근거 구간과 함께 기록하고, 날짜·범위는 원문 표기를 그대로 사용한다. 불분명하면 ‘확인 필요’로 표시한다.
- 필수 섹션에 해당하는 내용이 없으면 ‘언급 없음’으로 표시하고 내용을 만들지 않는다.
- 강의 기본 스타일은 A 단계부터 제공하고, 세미나·회의·일반 기본 스타일과 편집 기능은 B 단계에서 제공한다.

- **CAT-01:** 기본 분류의 스타일을 편집하고 제품 기본값으로 복원할 수 있다.
- **CAT-02:** 사용자 정의 상위 분류를 생성·수정·삭제할 수 있다. 스타일을 설정하지 않으면 ‘일반’ 기본 스타일을 적용한다.
- **CAT-03:** 상위 분류 아래 세부 분류를 생성할 수 있다. 예: 강의 → 운영체제, 강의 → 리눅스보안실습.
- **CAT-04:** 세부 분류는 상위 규칙을 상속하고, 용어 설명이나 추가 섹션 등 세부 스타일을 더한다. 세부 스타일이 비어 있으면 상위 규칙만 적용한다.
- **CAT-05:** 충돌 시 상위 분류 규칙이 우선한다. 예를 들어 상위가 ‘반드시 복습 항목 포함’, 하위가 ‘복습 항목 제외’이면 복습 항목을 유지하고 충돌을 표시한다.
- **CAT-06:** 초기 계층은 상위·하위의 2단계로 제공한다. 데이터 구조는 향후 계층 확장을 고려하되 다단계 UI는 현재 범위에 포함하지 않는다.
- **CAT-07:** 분류 삭제 시 기존 녹음과 요약을 연쇄 삭제하지 않는다. 기존 결과의 적용 규칙은 보존하고, 이후 작업에는 새 분류를 선택하게 한다.

### 6.4 요약 커스터마이징 규약

초기에는 구조화된 필드와 제한적인 추가 지시 입력으로 구성한다. 복잡한 자체 문법이나 코드 실행은 도입하지 않는다.

| 필드 | 의미 | 예시 |
| --- | --- | --- |
| 목적 | 요약의 사용 목적 | 시험 대비 복습 |
| 상세도 | 짧게·보통·자세히 | 자세히 |
| 문체 | 기본 표현 방식 | 간결한 설명체 |
| 필수 섹션 | 반드시 포함할 출력 구조 | 핵심 개념, 예제, 복습 질문 |
| 강조 항목 | 집중해서 정리할 내용 | 개념 간 차이, 실습 명령어 |
| 용어 표기 | 용어의 표현 방식 | 한국어 설명과 영문 원어 병기 |
| 추가 지시 | 위 필드를 보완하는 자연어 지시 | 코드 예제가 있으면 코드 블록으로 정리 |

적용 우선순위는 **제품의 데이터·근거·외부 통신 정책 → 상위 분류 규칙 → 하위 분류의 추가 규칙 → 참고 자료 내용**이다. 사용자 토글로 금지한 검색이나 이미지 생성을 스타일 문장으로 활성화할 수 없다. 원문과 첨부 자료는 데이터이며 앱 동작을 변경하는 지시로 실행하지 않는다.

- **STYLE-01:** 필드별 도움말, 예시, 상속 및 충돌 규칙을 편집 화면에 제공한다.
- **STYLE-02:** 저장 전에 비어 있는 필수값과 구조적 충돌을 검사하고, 실제 적용될 통합 규칙을 보여준다.
- **STYLE-03:** 자연어 충돌을 완벽하게 탐지한다고 가정하지 않는다. 명시적 필드 충돌은 결정적으로 처리하고, 추가 지시는 상위 우선 규칙에 따라 적용한다.
- **STYLE-04:** 규약에 버전을 부여하고 추후 필드 추가 시 기존 설정을 마이그레이션한다.

### 6.5 추가 자료

PDF·PPTX 연동은 B 단계, 자료 이미지 캡처(MAT-05)는 C 단계에서 제공한다.

- **MAT-01:** 녹음 시작 전이나 다시 요약 전에 여러 PDF·PPTX 파일을 첨부·제거할 수 있다. 구형 `.ppt`는 지원 여부를 별도 검증하고 미지원 시 변환 안내를 제공한다.
- **MAT-02:** 자료의 텍스트와 페이지·슬라이드 위치를 로컬에서 추출한다. 스캔 문서는 로컬 OCR 지원 가능성을 검증하고, 미지원 또는 추출 실패를 사용자에게 알린다.
- **MAT-03:** 녹음 내용과 관련된 자료 구간을 찾아 설명을 보강하고 파일명과 페이지·슬라이드를 출처로 기록한다.
- **MAT-04:** 녹음과 자료가 상충하면 임의로 하나를 확정하지 않고 차이를 표시한다.
- **MAT-05:** 이미지 사용이 허용된 경우 모델이 관련 페이지 또는 영역을 선택하고, 앱이 해당 위치를 렌더링·캡처하여 요약에 첨부한다.
- **MAT-06:** 코드, 명령어, 구조화된 설명은 코드 블록으로 표현할 수 있으며 Notion 전송에서도 해당 구조를 유지한다.
- **MAT-07:** 암호화, 손상, 미지원 형식, 크기 초과 파일은 오류를 표시한다. 사용자는 해당 자료를 제외하고 녹음만으로 계속 진행할 수 있다.

수용 기준: 보강 내용에 자료 출처가 표시되고, 이미지의 실제 페이지와 표시된 출처가 일치해야 한다. 파일 수·크기·페이지 제한은 기준 기기 검증 후 UI에 명시한다.

### 6.6 요약 전 세부 옵션

다음 기본값은 초기 제품 제안이며 사용자가 변경할 수 있다. 실행 중인 작업에는 시작 시점의 옵션을 적용하며, 녹음 중 미리 처리에는 녹음 시작 시점의 옵션을 적용한다. A 단계는 아래 기본값으로 동작하고, 옵션 편집과 강조 입력은 B 단계, 이미지·검색·교정 기능은 C 단계에서 제공한다.

| 옵션 | 기본값 | 허용 시 | 비허용 시 |
| --- | --- | --- | --- |
| 이미지 생성 허용 | 꺼짐 | 첨부 자료 이미지 추출 및 설치된 로컬 모델의 이미지 생성 허용 | 새로운 이미지 첨부 없이 텍스트·코드 블록으로 구성 |
| 외부 검색 허용 | 꺼짐 | 필요한 최소 검색어로 내용·용어 검증 | 검색을 위한 외부 통신 금지 |
| 대명사 교정 허용 | 꺼짐 | 문맥과 검색 결과에 근거해 전공 용어·고유명사 교정 | 검색 기반 자동 용어 교정 금지 |
| 불필요 내용 필터링 허용 | 켜짐 | 주제와 관련성이 낮은 잡담도 적극 제외 | 가능한 한 전체 내용을 요약하되 주제와 완전히 무관한 발언만 제외 |

‘대명사 교정’은 원 요구사항의 명칭을 보존한 것으로, 실제 대상은 `mutex`, `time slice` 등의 **전문 용어 및 고유명사**다. UI 명칭은 이해하기 쉬운 ‘전문 용어·고유명사 교정’으로 제안한다.

- **OPT-01:** 이미지 허용 시 토글 하단에 **“AI 이미지 생성은 부정확 할 수 있습니다.”**를 fade in으로 표시한다. 동작 감소 설정에서는 애니메이션 없이 표시한다.
- **OPT-02:** 이미지 허용은 이미지 삽입의 의무가 아니다. 원자료 캡처와 AI 생성 이미지를 구분하고 생성 이미지를 근거 자료처럼 사용하지 않는다. 로컬 생성 모델이 없으면 캡처 또는 텍스트로 처리한다.
- **OPT-03:** 외부 검색을 끄면 용어 교정을 즉시 비활성화하고 저장값도 꺼짐으로 변경한다. 외부 검색을 다시 켜도 교정을 자동으로 켜지 않는다.
- **OPT-04:** 검색 기반 교정은 원문·교정안·근거 링크를 확인할 수 있게 한다. 근거가 불충분하면 원문을 유지하고 확인 필요로 표시한다.
- **OPT-05:** 검색 실패 시 로컬 요약을 계속하고 검증하지 못한 항목을 표시한다. 외부 검색 공급자는 과금 없는 사용 조건을 검증한 후 채택하며, 조건을 충족하는 공급자가 없으면 검색 기능을 보류하고 사유를 기록한다.
- **OPT-06:** 필터링은 주제 관련성으로 판단한다. 정치·종교 발언도 강의나 회의의 주제에 해당하면 보존하며, 특정 단어가 있다는 이유만으로 제거하지 않는다.
- **OPT-07:** 필터링은 요약 반영 범위만 변경한다. 원본 음성과 전사문은 삭제하지 않으며 제외 구간을 확인할 수 있어야 한다.
- **OPT-08:** 추가 입력란으로 이번 요약에서 강조할 내용을 받을 수 있다. 분류의 필수 규칙과 옵션의 금지 사항을 덮어쓰지 못한다.

강의 자료나 용어 사전에 근거한 로컬 용어 교정을 검색 기반 교정과 어떻게 구분할지는 C 단계 착수 시 결정한다.

### 6.7 Notion 연동

Notion 연동은 B 단계에서 제공한다.

- **NOT-01:** 사용자가 명시적으로 연결을 선택하면 Notion에서 직접 만든 내부 연결의 토큰을 입력받아 연결한다. 연결 생성, 토큰 확인, 대상 페이지 공유 절차를 앱에서 안내한다. 서비스 자체 계정은 생성하지 않는다.
- **NOT-02:** 공개 연동의 OAuth 로그인은 토큰 교환에 비밀정보(client_secret)가 필요하여 운영 서버나 앱에 포함한 비밀정보 없이 구현할 수 없으므로 제공하지 않는다(2026-09-17 공식 문서 확인). 토큰은 Windows 자격 증명 관리자에 저장하고 일반 설정·로그에 기록하지 않는다. 내부 연결은 워크스페이스 소유자만 만들 수 있음을 안내한다. API의 무과금·요청 제한 조건은 구현 전에 공식 문서로 확인한다.
- **NOT-03:** 연결에 공유된 페이지 중에서 대상을 선택하거나 페이지 링크를 입력받아 접근 권한을 검증한다.
- **NOT-04:** 기본 대상 페이지를 저장하고 전송 직전에 변경할 수 있다. Notion의 ‘경로’는 폴더 문자열이 아닌 워크스페이스 및 상위 페이지 식별자로 관리한다.
- **NOT-05:** 초기 전송 방식은 선택한 상위 페이지 아래 새 요약 페이지 생성으로 한다. 기존 페이지 덮어쓰기는 별도 요구사항 확정 전 제공하지 않는다.
- **NOT-06:** 제목, 분류, 생성일, 본문, 제목 계층, 목록, 코드 블록과 출처를 매핑한다. 이미지는 현재 API의 지원 방식과 무과금 조건을 검증해 전송하고, 실패 시 로컬 이미지를 보존하며 누락 상태를 알린다.
- **NOT-07:** 결과 검토 후 ‘Notion에 보내기’를 명시적으로 실행한다. 기본 전송 대상은 최종 요약과 사용자가 포함한 자료 이미지이며, 원본 음성·전체 전사문·첨부 파일 전체를 자동 전송하지 않는다.
- **NOT-08:** 권한 부족, 인증 만료, 네트워크 오류, 부분 전송 실패를 구분한다. 로컬 결과와 전송된 페이지 식별자를 보존하여 재시도 시 중복 생성을 방지한다.
- **NOT-09:** 연결 해제 시 로컬에 저장한 토큰을 삭제한다. 이미 생성한 Notion 페이지는 자동 삭제하지 않는다.

수용 기준: Notion 미연결 상태에서도 핵심 기능을 완료할 수 있고, 연결 상태에서는 지정한 대상에 결과가 생성되며 페이지 링크를 확인할 수 있어야 한다. 이미지 전송, 요청 제한 등 API 세부 제약은 구현 시점의 공식 문서와 실제 검증으로 확정한다.

## 8. 모델 개량·학습·튜닝 요구사항

### 8.1 프로젝트 전용 LLM 지역화 원칙

기준 모델은 **Qwen3-8B**, 초기 실행본은 제작사 공식 **Q5_K_M GGUF**로 확정한다. 배포 파일과 revision은 [모델 선정 기록](decisions/0004-llm-selection.md), 제거 범위·LoRA 학습·출시 기준은 [지역화 실행 계획](LLM-SPECIALIZATION.md)을 따른다. 학습 적용 여부는 평가 후 결정하며, 실제로 학습을 완료하기 전에는 원본을 자체 개량 모델로 표시하지 않는다.

**프로젝트에 사용할 로컬 LLM은 우리 프로젝트에서 맡는 역할에 필요 없는 도구 및 기능을 제거하여 경량화하고, 필요한 도구와 기능의 성능을 더욱 높이는 ‘지역화’를 적용한다.** 이 문서에서 지역화는 언어 번역이나 지역 설정이 아니라 Just a Click!의 목적에 맞춘 모델·추론 환경·도구 구성의 특화를 의미한다.

- 핵심 강화 대상은 한국어·전공 용어 이해, 장문 요약, 분류별 스타일 준수, 자료와 전사 내용의 연관 분석, 근거 보존 및 구조화된 결과 생성이다.
- 제품 요구사항에 필요하지 않은 범용 도구 호출, 외부 서비스 연결, 실행 모듈과 의존성은 기본 구성에서 제외한다. 선택 기능은 필요할 때 별도 모듈로 활성화한다.
- 도구·런타임 기능을 제거하는 것과 모델 가중치를 줄이는 것은 구분한다. 도구를 제외했다고 모델의 지식이나 파라미터가 제거되거나 추론 속도가 개선되었다고 간주하지 않는다.
- 모델 자체의 경량화와 역량 강화는 양자화·증류·가지치기·학습·튜닝 등을 후보로 검증하며, 모든 기법의 적용을 의무화하지 않는다. 품질과 자원 사용의 실측 개선이 확인된 방법을 채택한다.
- 필요한 기본 언어 이해·추론 역량과 PRD의 필수·선택 기능은 보존한다. 지역화를 이유로 요구 기능을 임의로 삭제하지 않는다.
- 지역화 전후를 동일 평가셋으로 비교하여 요약 품질, 처리 시간, 메모리, 설치 용량과 규칙 준수의 변화를 기록한다. 품질 우선과 녹음 종료 후 5분 노트·다시 요약 1시간 목표를 함께 검증한다.

### 8.2 개발 및 검증 절차

1. STT 후보와 확정된 Qwen3-8B 기준 LLM의 한국어 품질, 전공 용어 처리, 배포 조건, RAM·VRAM 요구량을 검증한다. LLM 교체는 측정 근거가 있는 별도 결정으로 관리한다.
2. 본인 강의로 평가셋을 구성한다. 강의 5개로 시작해 20개까지 늘리고, 회의·세미나 사례는 B 단계에서 추가한다. 정답 예시와 전사 오류 사례를 포함하고 학습 데이터와 평가 데이터를 분리한다.
3. 프롬프트와 출력 스키마, 분할·통합 전략, 용어 사전 및 자료 검색을 먼저 개선한다.
4. 평가 결과로 필요성이 확인되면 파인튜닝 및 경량화 방식을 적용한다. 유료 학습 API와 무료 클라우드 할당량은 사용하지 않으며, 사용 권한이 있는 연구실 PC의 NVIDIA CUDA 환경을 학습 자원 후보로 둔다.
5. 모델 교체 전 기존 평가셋에서 정확성·누락·규칙 준수·성능의 회귀를 확인한다. 교체 및 이전 버전 복귀를 고려한다.
6. 사용자 녹음을 운영자에게 자동 수집하거나 학습에 자동 사용하지 않는다. 초기 제품에 기기별 자동 학습을 필수 기능으로 요구하지 않는다. 강의 녹음·전사를 평가·학습 데이터로 쓰기 전에 교수자 등 권리자의 허락과 사용 범위를 확인한다.

## 9. 비기능 요구사항

### 9.1 성능과 안정성

- 긴 작업이 화면을 멈추게 하지 않아야 한다. 작업 취소와 단계별 진행 상태를 제공한다.
- 진행률은 백분율과 현재 단계를 함께 표시한다. 남은 작업(전사 구간, 구간 초안, 최종 통합)을 입력 토큰은 실제 값, 출력 토큰은 예상 값으로 가중해 계산한다. 예상이 바뀌어도 표시값이 줄어들지 않게 하고, 100%는 결과 저장이 끝났을 때만 표시한다.
- 녹음 중에는 녹음 저장과 전사를 LLM 처리보다 우선한다. 전사가 밀리거나 메모리가 부족하면 LLM 미리 처리를 멈추고, RAM 16GB에서 동시 실행이 불가하면 녹음 중 전사만 수행하는 순차 모드로 전환한다.
- 배터리 절약 조건에서는 LLM 미리 처리를 멈추고 종료 후 처리로 전환할 수 있으며, 이때 5분 목표 대상이 아님을 표시한다. 온라인 강의 재생을 방해하지 않도록 자원 사용을 조절한다.
- 모델 누락, 다운로드 실패, 메모리 부족 시 복구 방법을 제공한다.
- 최소 지원 기기(RAM 16GB 이상 Windows 10·11 노트북 기준), 권장 사양, 최대 검증 녹음 길이 및 첨부 용량을 출시 전에 측정하여 공개한다.

### 9.2 개인정보와 외부 통신

- 기본 원칙은 원본과 파생 데이터를 기기 안에 유지하는 것이다.
- 모델 다운로드, 외부 검색, Notion 전송의 목적과 데이터 범위를 구분한다. 검색 허용을 전체 녹음 업로드 허용으로 해석하지 않는다.
- 로그에 인증 토큰이나 원본 전체 내용을 기본 기록하지 않는다.
- 외부 검색 허용 여부와 Notion 연결 여부는 독립적으로 관리한다. 검색 비허용 상태에서도 사용자가 직접 요청한 Notion 전송은 가능하다.

### 9.3 접근성과 사용성

- 토글·입력·진행 상태는 키보드로 조작·확인 가능해야 한다.
- 오류와 활성 상태를 색상만으로 표현하지 않는다.
- 사용자에게 설치된 모델, 로컬 처리 상태, 외부 전송이 필요한 동작을 이해하기 쉽게 표시한다.

### 9.4 확장 가능한 구조

- 녹음 수집, STT, 요약 엔진, 자료 파서, 검색 공급자, 결과 렌더러, Notion 커넥터를 교체 가능한 경계로 나눈다. 추론 런타임은 앱과 별도 프로세스로 실행한다.
- 결과는 Notion 블록에 직접 종속시키지 않고 제목·문단·목록·코드·이미지·출처 등을 표현하는 내부 구조로 저장한다.
- 옵션과 규약에는 버전을 두며, 새 기능이 생겨도 과거 요약을 읽을 수 있게 한다.
- 이 구조는 확장 기반이며, 초기 버전에 공개 확장 API나 플러그인 로더를 구현해야 한다는 의미는 아니다.

## 10. 보류 기능 및 확장 후보

### 10.1 라이브러리 고급 기능

라이브러리의 목록·검색·다시 요약·삭제는 6.8에서 제공한다. 여러 요약 버전의 비교 화면, 일괄 정리 등 고급 기능은 보류한다. 구현 시 원본과 파생 결과의 관계를 유지한다.

### 10.2 업데이트

배포 후 새 버전 확인과 UI 또는 간단한 명령어를 통한 업데이트를 검토한다. 필수 서버 유지비가 발생하면 제외한다. 도입 시 패키지 무결성, 실패 복구, 로컬 데이터 호환성을 요구사항에 추가한다.

### 10.3 확장 기능

- 사용자 또는 운영자가 개발하는 코드 작성 지원, 이미지 생성 고급화, 성능 최적화 등의 확장을 검토한다.
- 개발 로드맵, 인터페이스와 배포 규약을 제공한다.
- 사용자 제출 → 운영자 검토·승인 → 등록 흐름을 검토한다.
- 등록 메타데이터는 이름, 대표 이미지, 설명, 사용 방법을 포함한다.
- 실행 권한, 버전 호환성, 신뢰성 검토 및 제거 방법을 별도 설계한다.
- 중앙 등록·배포 서버의 비용이 필요하면 제외하거나 비용 없는 운영 방식을 검토한다.

### 10.4 기타 추가 가능 기능

기존 음성 파일 가져오기, 입력 혼합, 화자 구분, 영어 강의·다국어, Markdown·PDF 등 추가 내보내기 형식, 용어 사전, 추가 문서 형식, 불특정 다수 공개 배포 등을 향후 제안할 수 있다. 모두 확정 범위가 아니며, 사용자 가치·로컬 실행 가능성·비용·성능·데이터 정책을 평가하여 별도 요구사항으로 편입한다.

## 12. 출시 전 수용 시나리오

각 단계는 해당 단계와 이전 단계의 시나리오를 통과해야 한다.

**A 단계 — 수업용 최소 빌드**

1. **오프라인 강의 흐름:** 모델 준비 후 네트워크가 없는 상태에서 마이크 녹음(일시정지 포함), 녹음 중 전사·구간 초안, 종료 후 5분 노트 저장, 재실행 후 결과 열기를 완료한다.
2. **시스템 소리:** 온라인 강의 소리를 녹음하여 같은 흐름을 완료한다.
3. **시간·진행률:** AC 전원·"최고 성능" 모드의 기준 기기에서 2~3시간 강의의 녹음 종료 후 노트 저장 시간을 측정한다. 배터리 사용 시 결과도 참고로 기록한다. 진행률은 줄어들지 않으며 저장이 끝났을 때만 100%가 된다.
4. **정밀 정리:** 5분 노트 이후 정밀 버전이 만들어진다. 품질 검사에 실패하면 기본 보기가 바뀌지 않고, 사용자가 수정한 노트는 자동 교체되지 않는다. 새 녹음을 시작하면 정밀 정리가 일시정지된다.
5. **근거:** 시험·과제·공지 항목에는 원문 구간 근거가 있고, 원문에 없는 날짜·범위를 만들지 않는다.
6. **외부 통신:** 검색과 Notion을 사용하지 않는 작업에서 입력 데이터의 외부 전송이 없다.
7. **실패 복구:** 메모리 부족, 작업 취소, 앱 비정상 종료가 발생해도 녹음과 저장된 결과가 남아 다시 처리할 수 있다. 순차 모드·배터리 절약 전환은 화면과 기록에 표시된다.

**B 단계 — 첫 공유 버전**

8. **분류 기본값:** 새 상위 분류를 스타일 없이 생성하면 일반 기본 스타일이 적용된다.
9. **규칙 상속:** 강의 → 운영체제의 하위 스타일은 상위 필수 섹션을 유지하며 추가 설명을 반영한다. 충돌한 하위 지시로 상위 규칙이 제거되지 않는다.
10. **필터링:** 필터링 수준에 따라 요약 반영 범위가 달라져도 원본 전사문은 유지된다. 주제와 관련된 정치·종교 내용은 보존된다.
11. **자료:** PDF·PPTX를 첨부한 요약에서 보강 내용과 출처 페이지를 확인하고, 손상된 자료를 제외해 계속 진행할 수 있다.
12. **전사 수정:** 전사를 고치면 바뀐 구간만 다시 처리되고 새 노트 버전이 만들어지며 기존 버전은 보존된다.
13. **라이브러리:** 과목·날짜·내용으로 강의를 찾고, 다른 스타일로 다시 요약한 시간을 측정하며, 삭제 범위를 확인한 뒤 삭제한다.
14. **Notion:** 서비스 계정 없이 내부 연결 토큰으로 연결하고 지정한 상위 페이지 아래 새 요약 페이지를 생성한다. 연결을 해제하면 로컬 토큰이 삭제된다.
15. **Notion 재시도:** 부분 전송이나 응답 유실 후 기존 페이지 상태를 확인하여 중복을 방지하고 로컬 요약을 보존한다.
16. **설치:** Install Manager로 RAM 16GB 노트북의 Windows 10·11에 설치하고 모델 무결성 확인 후 핵심 흐름을 완료한다.
17. **모델 변경:** 모델 또는 스타일 규약 업데이트 이후 기존 데이터를 열 수 있고, 평가셋에서 품질 회귀 여부를 확인한다.

**C 단계 — 확장**

18. **이미지:** 허용 시 경고가 표시되고, 비허용 시 캡처 및 생성 이미지가 새로 삽입되지 않는다. 코드 블록은 정상 제공된다.
19. **검색:** 검색을 끄면 용어 교정도 꺼지고 비활성화된다. 검색 실패 시 검증 실패 표시와 함께 로컬 요약을 완료한다.
