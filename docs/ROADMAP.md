# Just a Click! 개발 로드맵

- 버전: v0.3
- 작성일: 2026-09-16
- 기준 문서: [PRD](PRD.md)
- 현재 상태: M0의 짧은 로컬 LLM 실행 시험 완료, 앱 구현·STT·장문 검증 미착수
- 원칙: 유료 API 미사용, 계정 없는 로컬 저장, 오프라인 핵심 기능, 추후 확장 가능성 유지

## 1. 진행 방식

일정은 인력·지원 기기·모델 측정 결과가 없는 상태에서 확정하지 않는다. 단계별 완료 조건을 기준으로 진행하며, M0 완료 후 작업량과 우선순위를 바탕으로 일정을 산정한다.

상태는 `미착수 → 진행 중 → 검증 중 → 완료`로 관리한다. 차단된 작업은 원인과 재개 조건을 기록한다. 코드 작성만으로 완료 처리하지 않으며 각 단계의 산출물과 수용 기준이 충족되어야 한다.

| 단계 | 목표 | 의존 단계 | 현재 상태 |
| --- | --- | --- | --- |
| M0 | 기술 검증과 실행 환경 결정 | 없음 | 진행 중 |
| M1 | 앱·로컬 저장·작업 처리 기반 | M0 | 미착수 |
| M2 | 녹음과 전사 검토 | M1 | 미착수 |
| M3 | 로컬 요약과 분류·스타일 | M2 | 미착수 |
| M4 | 오프라인 MVP 안정화·배포 패키지 | M3 | 미착수 |
| M5 | 첨부 자료 분석과 이미지 추출 | M4 | 미착수 |
| M6 | 선택적 Notion 연결·전송 | M4 및 M0 인증 검증 | 미착수 |
| M7 | 외부 검색과 전문 용어 교정 | M4 및 무료 검색 검증 | 미착수 |
| M8 | 모델 튜닝·로컬 이미지 생성 고도화 | M4, 자료 관련 평가는 M5 | 미착수 |

M5·M6·M7은 공통 기반 이후 서로 독립적인 개발 트랙으로 진행할 수 있다. 자료 이미지의 Notion 전송 통합 검증은 M5와 M6 모두 완료된 뒤 수행한다. 이 구분은 구현 의존 관계이며 에이전트 위임을 요구하는 지침은 아니다.

## 2. M0 — 기술 검증과 의사결정

### 작업

- [x] 실행 구조·모델 후보 조사와 [M0 검증 계획](M0-VALIDATION.md)을 작성한다. 실제 모델 채택·추론 검증은 미완료.
- [x] 초기 지원 OS와 앱 실행 형태를 결정한다: Windows 10·11용 exe 데스크톱 앱.
- [x] 설치 방향을 결정한다: 별도 Install Manager 제작, 설치 시 로컬 LLM 함께 구축.
- [x] 모델 공급 방식을 결정한다: Install Manager가 설치 중 다운로드하고 무결성 검증.
- [x] 시간 구간을 확정한다: 전사 완료 후 요약 실행 요청부터 최종 로컬 저장까지 최대 120초.
- [x] 기준 LLM을 Qwen3-8B 공식 Q5_K_M으로 확정하고 revision·파일 해시를 기록한다.
- [x] 모델 다운로드·SHA-256 확인, llama.cpp b10994 고정, CPU·Vulkan 합성 회의문 각 3회 실행과 [결과 기록](validation/2026-09-17-llm-smoke.md)을 완료한다.
- [x] 회의 출력 계약·회귀 테스트와 [Vulkan 스키마·입력 처리 진단](validation/2026-09-17-contract-prefill.md)을 수행한다. 8,192토큰 기본 배치 실패 및 작은 배치 재시험 결과를 함께 기록한다.
- [x] [지역화·LoRA 개량 계획](LLM-SPECIALIZATION.md)과 내부 품질 기준을 확정한다.
- [ ] 최대 120초 요약 목표와 실제 품질·성능을 함께 검증한다.
- [ ] Install Manager의 모델 동봉·다운로드 정책, STT 런타임 설치, 무결성 확인·중단 복구·제거 범위를 정의한다.
- [x] 기준 기기의 CPU·RAM·GPU 보고값·여유 저장 공간을 기록한다. [조회 결과](decisions/0001-target-environment.md).
- [ ] 추론 백엔드에서 실제 사용 가능한 GPU 메모리와 가속 지원을 검증한다.
- [x] 최대 녹음 길이를 정한다: 한 건 4시간.
- [ ] 로컬 STT 및 LLM 후보의 한국어·영어 혼용 품질, 라이선스, 배포·튜닝 조건을 확인한다.
- [ ] 짧은 녹음으로 로컬 전사 → 요약 수직 흐름을 검증한다.
- [ ] 최대 4시간 녹음의 분할 처리, 메모리 사용량, 처리 시간을 측정한다.
- [ ] 로컬 파일·메타데이터·보안 저장소와 백그라운드 작업 실행 방식을 결정한다.
- [ ] Notion 로그인 인증이 비밀정보 보호와 운영비 0원을 동시에 충족할 수 있는지 공식 문서로 검증한다.
- [ ] 외부 검색의 무과금 제공 방식과 이용 조건을 조사하고 불가능하면 보류 사유를 남긴다.
- [ ] 강의·회의·세미나 평가셋의 형식과 품질 합격 기준을 정한다.

### 산출물

- `docs/decisions/`의 기술 스택·모델·저장·인증 결정 기록.
- 기준 기기, 입력 길이, 모델 버전, 시간·메모리·품질이 포함된 검증 결과.
- MVP 범위, 최소 지원 사양, 데이터·자료 용량 제한 초안.

### 완료 조건

과금 API 없이 기준 기기에서 실제 음성의 로컬 전사와 요약이 작동한다. 핵심 기술 선택에 근거가 있고 라이선스 문제가 남지 않는다. Notion·검색은 구현 가능 여부 또는 보류 사유가 명시되어야 하며, 선택적 연동의 차단이 로컬 MVP를 막지 않는다.

## 3. M1 — 앱과 데이터 기반

### 작업

- [ ] 결정된 스택으로 앱 골격과 개발·실행 명령을 구성한다.
- [ ] 모델 준비·녹음·전사 검토·요약 설정·결과·설정 화면의 탐색 구조를 만든다.
- [ ] 녹음, 전사, 분류, 자료, 작업, 요약 결과의 식별자와 데이터 스키마를 정의한다.
- [ ] 대용량 파일과 메타데이터를 분리하고 스키마 버전을 기록한다.
- [ ] 작업 상태를 대기·실행·성공·실패·취소로 관리하고 단계별 오류를 표현한다.
- [ ] 모델 다운로드·설치 상태, 저장 위치, 디스크 공간 오류를 처리한다.
- [ ] 데이터 재열기, 삭제 범위, 비정상 종료 시 복구의 기반을 구현한다.
- [ ] 비밀정보·미디어·모델·캐시 제외 규칙과 최소 개발 검증 명령을 추가한다.

### 완료 조건

앱을 실행하고 종료한 뒤 샘플 작업과 설정을 다시 열 수 있다. 작업 실패와 취소가 기존 데이터를 손상시키지 않는다. 로그인이나 외부 서버가 실행에 필요하지 않다.

## 4. M2 — 녹음과 로컬 전사

관련 PRD: REC-01~03, STT-01~03.

### 작업

- [ ] 마이크 권한 요청, 입력 상태, 녹음 시간 표시를 구현한다.
- [ ] 녹음 시작·일시정지·재개·종료와 점진 저장을 구현한다.
- [ ] 선택한 로컬 STT를 연결하고 긴 녹음의 분할·진행·취소를 처리한다.
- [ ] 타임스탬프가 있는 전사문과 해당 구간 재생을 연결한다.
- [ ] 원본 전사와 사용자 수정본을 분리하고 저장한다.
- [ ] 권한 거부, 장치 오류, 디스크 부족, 모델 누락 및 비정상 종료를 검증한다.

### 완료 조건

실제 마이크 녹음 → 로컬 전사 → 구간 재생 → 수정 → 재열기가 가능하다. 일시정지 구간이 녹음에 들어가지 않고 복구 가능한 마지막 저장 구간을 확인할 수 있다.

## 5. M3 — 요약과 스타일 설정

관련 PRD: SUM-01~06, CAT-01~07, STYLE-01~04, 필터링 및 추가 입력 옵션.

### 작업

- [ ] 강의·회의·세미나·일반 기본 스타일을 제공한다.
- [ ] 사용자 분류와 한 단계 세부 분류의 생성·수정·삭제를 구현한다.
- [ ] 구조화된 스타일 필드, 기본값 복원, 도움말, 통합 규칙 미리보기를 구현한다.
- [ ] 상위 우선 상속과 명시적 필드 충돌 처리를 구현한다.
- [ ] 로컬 LLM의 장문 분할·통합 요약을 연결한다.
- [ ] 제목·문단·목록·코드·근거를 표현하는 내부 결과 구조를 만든다.
- [ ] 불필요 내용 필터링과 이번 요약의 강조 입력을 제공한다.
- [ ] 근거 구간·불확실성·제외 내역을 표시하고 결과 편집·저장·복사를 구현한다.
- [ ] 입력 버전, 모델, 옵션, 적용 규칙 스냅샷을 저장한다.

### 완료 조건

수정 전사문으로 분류별 요약을 생성할 수 있다. 스타일 미설정 기본값, 상위 우선 충돌 처리, 원본 보존이 검증된다. 장문 평가와 사실 정확성 기준을 충족하며 모델이 만든 수치·일정·담당자를 근거 없이 확정하지 않도록 평가한다.

## 6. M4 — MVP 검증과 배포 준비

### 작업

- [ ] 모델 준비 후 네트워크를 차단한 상태로 전체 흐름을 검증한다.
- [ ] 실제 강의·회의·세미나 평가셋으로 품질과 처리 시간을 측정한다.
- [ ] 최대 4시간 녹음과 전사·요약, 메모리 부족, 디스크 부족, 취소·재시도·복구를 확인한다.
- [ ] 키보드 조작, 오류 안내, 진행 표시를 검토한다.
- [ ] Windows 10·11용 exe 앱과 별도 Install Manager를 구현하고 로컬 LLM 구축 및 STT 실행 환경 준비를 연결한다.
- [ ] 설치 실패·재시도·모델 무결성·경로 처리 및 제거 시 사용자 데이터 보존 정책을 검증한다.
- [ ] 지원 OS의 로컬 설치 패키지와 모델 설치 안내를 준비한다.
- [ ] 모델 라이선스와 재배포 고지, 데이터 위치·삭제 방법을 문서화한다.
- [ ] PRD의 공통 수용 시나리오 1~6을 실행하고 결과를 기록한다.

### 완료 조건

기준 환경에서 설치 후 녹음 → 전사 → 분류별 요약 → 로컬 저장 → 재열기를 완료한다. 원본의 외부 전송 없이 오프라인으로 동작하며, 품질·성능 결과와 알려진 제한이 기록되어 있다. 패키지 생성은 공개 배포와 구분하며 실제 공개는 사용자 요청 범위에 따라 진행한다.

## 7. M5 — 추가 자료와 이미지 추출

관련 PRD: MAT-01~07, OPT-01~02.

### 작업

- [ ] PDF·PPTX 첨부·제거와 형식·크기 검증을 구현한다.
- [ ] 텍스트와 페이지·슬라이드 위치를 로컬에서 추출한다.
- [ ] 스캔 문서의 OCR 지원 여부를 검증하고 실패·미지원 안내를 구현한다.
- [ ] 전사 구간과 자료의 관련 부분을 연결해 요약에 보강한다.
- [ ] 자료 간 충돌과 파일·페이지 출처를 표시한다.
- [ ] 이미지 허용 토글, 경고 문구, 동작 감소 설정을 반영한다.
- [ ] 모델이 선택한 페이지·영역을 실제로 캡처하고 결과와 연결한다.
- [ ] 이미지 비허용 시 텍스트·코드 블록으로 결과를 구성한다.

### 완료 조건

보강된 내용과 이미지의 출처가 실제 첨부 자료와 일치한다. 손상된 자료를 제외한 채 계속 진행할 수 있고 이미지 비허용 시 캡처 이미지가 삽입되지 않는다. 로컬 이미지 생성 모델은 이 단계의 필수 조건이 아니다.

## 8. M6 — Notion 연동

관련 PRD: NOT-01~09. M0에서 인증 구조가 검증된 경우 착수한다.

### 작업

- [ ] 선택적 Notion 로그인과 안전한 인증 정보 저장·연결 해제를 구현한다.
- [ ] 접근 가능한 워크스페이스·상위 페이지 선택과 기본 대상 저장을 구현한다.
- [ ] 내부 결과를 Notion 제목·목록·코드·출처 블록으로 변환한다.
- [ ] 사용자 전송 동작으로 상위 페이지 아래 새 요약 페이지를 생성한다.
- [ ] 원격 페이지 식별자와 전송 상태를 저장하고 중복 없는 재시도를 구현한다.
- [ ] 인증 만료·권한 오류·부분 실패·응답 유실을 처리한다.
- [ ] M5 완료 후 이미지 전송과 누락 상태 안내를 통합 검증한다.

### 완료 조건

사용자가 고른 위치에 요약이 생성되고 결과 링크를 확인한다. 원본 음성·전체 전사·첨부 전체가 자동 전송되지 않는다. 부분 실패 이후 재시도로 중복 페이지가 생기지 않으며 연결 해제 후 로컬 인증 정보가 삭제된다.

## 9. M7 — 외부 검색과 전문 용어 교정

관련 PRD: OPT-03~05. 과금 없는 검색 방식과 약관을 검증한 경우 착수한다.

### 작업

- [ ] 기본 꺼짐인 검색 옵션과 하위 용어 교정 옵션을 구현한다.
- [ ] 검색을 끄면 교정값도 꺼지고 비활성화되도록 구현한다.
- [ ] 최소 검색어만 전송하는 검색 경계를 만든다.
- [ ] 원문·교정안·출처 링크를 결과에서 비교할 수 있게 한다.
- [ ] 불충분한 근거 및 검색 실패 시 원문 유지·확인 필요 상태를 제공한다.
- [ ] 검색 결과에 포함된 지시문이 앱의 정책이나 옵션을 바꾸지 못하도록 처리한다.

### 완료 조건

검색 비허용 상태에서 검색 통신이 없고, 허용 상태에서는 교정 근거를 확인할 수 있다. 검색 실패가 로컬 요약을 중단하지 않으며 검색 옵션과 Notion 전송이 독립적으로 동작한다.

## 10. M8 — 모델 및 이미지 생성 고도화

확정된 Qwen3-8B에 [지역화 실행 계획](LLM-SPECIALIZATION.md)을 적용한다. 초기 런타임 최소 구성은 M0~M1, 입력·출력 및 근거 구조는 M3부터 적용한다. 이 단계에서는 검수 데이터 구축과 LoRA SFT·병합·GGUF 변환·Q5_K_M 양자화를 수행한다. 레이어 삭제·어휘 축소·증류는 v1 기본 범위에서 제외한다.

### 작업

- [ ] PRD의 역할별 필수·선택 기능과 불필요한 도구·모듈·의존성을 분류하고 최소 실행 구성을 정의한다.
- [ ] 불필요한 구성 요소를 제거하고 선택 기능을 분리하되 요구 기능의 사용 가능성을 유지한다.
- [ ] 모델 가중치 경량화와 도구 구성을 별도로 평가하고 지역화 전후 설치 용량·메모리·속도·품질을 비교한다.
- [ ] 누락·사실 오류·용어 오류·규칙 위반을 분류하고 우선 개선 대상을 정한다.
- [ ] 프롬프트·용어 사전·자료 검색·분할 전략을 기준 모델과 비교한다.
- [ ] 효과가 필요한 부분에 한해 로컬 학습·파인튜닝과 양자화를 검증한다.
- [ ] 학습·평가 데이터 분리와 사용 권한을 확인한다.
- [ ] 모델 교체 및 이전 버전 복귀와 저장 데이터 호환성을 검증한다.
- [ ] 선택 설치형 로컬 이미지 생성의 라이선스·메모리·속도를 검증한다.
- [ ] 생성 이미지 표시, 허용 옵션 준수, 모델 미설치 시 대체 동작을 구현한다.

### 완료 조건

기준 모델 대비 개선을 같은 평가 조건으로 입증하고 회귀 여부를 기록한다. 사용자 데이터 자동 수집과 유료 학습 API를 사용하지 않는다. 이미지 생성은 지원 기기에서 선택적으로 동작하며 원자료 근거와 구분된다.
