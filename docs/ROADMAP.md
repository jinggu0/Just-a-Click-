# Just a Click! 개발 로드맵

- 버전: v0.4
- 작성일: 2026-09-16 (최종 수정 2026-09-17)
- 기준 문서: [PRD](PRD.md), [범위 결정 0006](decisions/0006-lecture-first-product-scope.md)
- 현재 상태: M0 진행 중. 짧은 합성 입력의 로컬 LLM 실행과 회의 계약 진단을 마쳤고, 제품 범위를 강의 우선·단계적 출시로 재구성했다. 앱 구현·STT·실제 강의 검증은 미착수
- 원칙: 유료 API 미사용, 계정 없는 로컬 저장, 오프라인 핵심 기능, 추후 확장 가능성 유지

## 1. 진행 방식

일정은 인력·지원 기기·모델 측정 결과가 없는 상태에서 확정하지 않는다. 단계별 완료 조건을 기준으로 진행하며, M0의 핵심 검증 후 작업량과 우선순위를 바탕으로 일정을 산정한다. 목표는 2026년 2학기 중 A 빌드를 실제 수업에 쓰는 것이다.

상태는 `미착수 → 진행 중 → 검증 중 → 완료`로 관리한다. 차단된 작업은 원인과 재개 조건을 기록한다. 코드 작성만으로 완료 처리하지 않으며 각 단계의 산출물과 수용 기준이 충족되어야 한다.

| 단계 | 목표 | 의존 단계 | 현재 상태 |
| --- | --- | --- | --- |
| M0 | 기술 검증과 실행 환경 결정 | 없음 | 진행 중 |
| A | 수업용 최소 빌드(본인 사용) | M0 핵심 검증 | 미착수 |
| B | 첫 공유 버전 v1.0 | A | 미착수 |
| C | 확장 기능 | B, 항목별 사전 검증 | 미착수 |

v0.3의 M1~M8은 다음과 같이 재배치했다. 앱 기반·녹음·전사(M1·M2)와 강의 기본 요약(M3 일부)은 A, 스타일 편집·안정화·배포(M3 일부·M4)와 자료 근거·Notion(M5 일부·M6)은 B, 자료 이미지·검색·모델 고도화(M5 일부·M7·M8)는 C에 속한다.

C의 각 기능은 서로 독립적인 트랙으로 진행할 수 있다. 자료 이미지의 Notion 전송 통합 검증은 캡처 기능 완료 뒤 수행한다. 이 구분은 구현 의존 관계이며 에이전트 위임을 요구하는 지침은 아니다.

- [ ] 전사 구간과 자료의 관련 부분을 연결해 보강하고, 자료 간 충돌과 파일·페이지 출처를 표시한다.
- [ ] Notion 내부 연결 토큰의 입력·안내·자격 증명 관리자 저장·연결 해제를 구현한다.

### 완료 조건

공유 대상 환경에서 설치 후 녹음 → 노트 → 수정·다시 요약 → Notion 전송을 완료한다. 원본의 외부 전송 없이 핵심 흐름이 오프라인으로 동작하며, 품질·성능 결과와 알려진 제한이 기록되어 있다. 원본 음성·전체 전사·첨부 전체가 Notion에 자동 전송되지 않는다. 패키지 생성은 공개 배포와 구분하며 실제 공유 범위는 사용자 요청에 따른다.

## 5. C — 확장 기능

관련 PRD: MAT-05, OPT-01~05, 8장, 12장 시나리오 18~19. 지역화의 최소 런타임 구성은 A, 입력·출력·근거 구조는 A부터 적용하고, 학습 관련 작업은 이 단계에서 평가 결과에 따라 수행한다. 레이어 삭제·어휘 축소·증류는 v1 기본 범위에서 제외한다.

### 작업

- [ ] 이미지 허용 토글·경고 문구·동작 감소 설정을 반영하고, 모델이 선택한 자료 페이지·영역을 캡처해 결과와 출처에 연결한다. 비허용 시 텍스트·코드 블록으로 구성한다.
- [ ] 캡처 이미지의 Notion 전송과 누락 상태 안내를 통합 검증한다.
- [ ] 무과금 검색 공급자를 검증한 뒤 기본 꺼짐인 검색·용어 교정 옵션, 최소 검색어 전송, 원문·교정안·출처 비교, 검색 실패 처리를 구현한다. 검색 결과에 포함된 지시문이 앱의 정책이나 옵션을 바꾸지 못하게 한다.
- [ ] 강의 자료·용어 사전 기반 로컬 용어 교정과 검색 옵션의 관계를 결정한다.
- [ ] 선택 설치형 로컬 이미지 생성의 모델·라이선스·메모리·속도를 검증하고, 생성 이미지 표시·허용 옵션 준수·모델 미설치 시 대체 동작을 구현한다.
- [ ] 누락·사실 오류·용어 오류·규칙 위반을 분류하고, 프롬프트·용어 사전·자료 검색·분할 전략을 기준 모델과 비교한다.
- [ ] 모델 가중치 경량화와 도구 구성을 별도로 평가하고 지역화 전후 설치 용량·메모리·속도·품질을 비교한다.
- [ ] 평가 결과로 학습 필요성을 판단하고, 필요하면 [지역화 계획](LLM-SPECIALIZATION.md)에 따라 연구실 PC의 CUDA 환경에서 LoRA 학습·병합·변환·양자화와 회귀 평가를 수행한다. 학습·평가 데이터 분리와 사용 권한을 확인한다.
- [ ] 모델 교체 및 이전 버전 복귀와 저장 데이터 호환성을 검증한다.
- [ ] PRD 12장의 C 단계 시나리오 18~19를 실행하고 결과를 기록한다.

### 완료 조건

각 기능이 수용 기준과 비용·외부 통신 조건을 충족한다. 검색 비허용 상태에서 검색 통신이 없고, 검색 실패가 로컬 요약을 중단하지 않는다. 이미지 생성은 지원 기기에서 선택적으로 동작하며 원자료 근거와 구분된다. 학습한 모델은 기준 모델 대비 개선을 같은 평가 조건으로 입증하고 회귀 여부를 기록하며, 사용자 데이터 자동 수집과 유료 학습 API를 사용하지 않는다.

## 7. 바로 다음 작업

**사용자 결정: 시간 목표 미달(추정)에 대한 다음 방향을 정한다.** [llama-bench 1차 판정](validation/2026-09-17-llama-bench.md)에서 지속 성능 기준 녹음 종료 후 시간은 350~364초(목표 300초), 3시간 강의 다시 요약은 3,718~3,956초(목표 3,600초)로 추정됐다. 녹음 종료 후 목표에 필요한 생성 속도는 4.32~4.52 tok/s로 현재보다 약 20~30% 높다.

선택지는 다음과 같다.
1. 사용자가 전원 모드를 '최고 성능'으로 바꾼 뒤 같은 측정을 반복한다.
2. 구간·최종 출력량이나 구간 길이를 조정하고 품질을 평가한다.
3. 녹음 종료 후 목표 시간을 조정한다.
4. SYCL 등 가속 경로를 비교하거나 모델 재검토를 결정한다.

측정 당시 전원 모드가 '최고의 전원 효율성'이었고 저전력 상태의 증거가 있어 1번을 먼저 권한다. 결정 전에는 모델·목표를 바꾸지 않는다. STT 측정(남은 작업 2·3)은 결정과 병행할 수 있다. 실제 음성 STT·장문 요약·Notion·검색·Windows 10 검증은 아직 미완료다.
