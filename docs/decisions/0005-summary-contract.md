# 0005 — 회의 요약 출력 계약과 입력 처리 진단

- 날짜: 2026-09-17
- 상태: 개발용 출력 계약 구현. 실제 GPU 검증 결과는 별도 보고서에 기록
- 배경: 초기 CPU 출력의 기한 누락, Vulkan 출력의 action 항목 구조 불일치

## 계약

`schemas/meeting-summary-v1.json`을 생성 제약과 로컬 검증의 공통 원본으로 사용한다. 모든 후속 작업은 `content`, `owner`, `deadline`, `source_refs`를 포함해야 한다. 언급하지 않은 담당자·기한은 null로 표현하며 생략이나 ‘미정’ 문자열로 대체하지 않는다.

- 필수 최상위 구조: schema_version, title, decisions, actions, open_questions.
- 예상하지 않은 속성, 빈 내용, 빈 출처 목록, 중복 출처와 존재하지 않는 출처 ID를 거부한다.
- 실제 입력의 출처 ID를 스키마 enum에 넣어 생성 단계에서도 제한한다.
- 담당자·기한의 비어 있지 않은 값은 인용된 원문의 표기를 그대로 사용하게 하고 로컬에서 존재 여부를 확인한다.
- 중복 JSON 키와 출력 길이 제한으로 종료된 응답은 유효한 JSON처럼 보이더라도 완료로 저장하지 않는다.
- 검증 실패 응답은 진단용 원응답으로 보존하고 accepted 결과 파일을 만들지 않는다. 개발용 fixture 검사 실패도 별도 표시한다.

검증 코드는 일반 JSON Schema 엔진이 아니라 이 저장소에서 사용하는 키워드만 지원하는 개발용 구현이다. 새로운 스키마 키워드가 생기면 지원 여부와 테스트를 함께 변경해야 한다. 앱 개발 시 계약을 유지하면서 실제 앱 언어·라이브러리에 맞게 옮길 수 있다.

## 검증의 한계

출처 ID가 유효하거나 원문에 이름이 등장한다는 것만으로 실제 담당 관계를 증명할 수 없다. 인용의 의미, 부정·취소, 핵심 내용 누락은 별도 검수 대상이다. 회의 smoke 입력의 회귀 검사는 해당 합성 사례 전용이며 다른 문서의 품질 점수로 사용하지 않는다.

상위·하위 스타일 상속, 강의·세미나 스키마와 자료·검색 출처는 이번 회의 계약 이후 확장한다. 이번 구현으로 전체 요약 파이프라인이 완성됐다고 간주하지 않는다.

## 속도 측정

요약 시간은 템플릿 적용·토큰 예산 확인·추론·계약 검증·accepted 결과 저장까지 포함한다. 모델 준비는 별도 기록하고 첫 요청과 합산한다. 입력과 출력 예약분이 컨텍스트를 넘으면 임의로 자르지 않고 분할이 필요하다는 오류를 낸다.

4,096·8,192토큰 시험은 합성 텍스트를 반복해 만든 토큰 배열을 입력하고 1토큰만 생성하는 **입력 처리량 진단**이다. 입력 토큰 수·truncated 여부를 확인하며, 실제 장문 요약이나 4시간 녹음 처리 결과로 표현하지 않는다. 모델·양자화·컨텍스트·스레드 수를 유지한 채 Flash Attention auto/on을 비교하되 한 번의 측정으로 최적 설정을 확정하지 않는다.
