# 0006 — 강의 우선 제품 범위와 단계적 출시

- 날짜: 2026-09-17
- 상태: 사용자 인터뷰로 제품 범위·흐름·시간 목표 확정. 시간·품질 목표의 달성은 미검증
- 변경하는 결정: [0003](0003-installation-and-performance.md)의 '전사 완료 후 요약 최대 120초' 목표, PRD v0.5의 로그인 방식 Notion 연동·라이브러리 보류·전사 중 사전 요약 제외 원칙
- 관련 결정: 앱 기술은 [0007](0007-app-stack.md)을 따른다.

## 1. 배경

M0 측정에서 기준 노트북(Intel Arc 140V, Vulkan)의 생성 속도는 초당 2.58~3.77토큰이었고, 329토큰짜리 회의 요약도 생성에만 112~127초가 걸렸다([진단 보고서](../validation/2026-09-17-contract-prefill.md)). 고정된 Qwen3-8B 토크나이저로 합성 회의문을 토큰화하면 한글 249음절이 225토큰이었다. 1건의 참고값이다.

발화 속도를 초당 2.5~4음절로 가정하면 2~3시간 강의는 약 2만~4만 토큰이다. 이 가정과 실측 속도로 계산하면 녹음 후 한 번에 요약하는 데 대략 15~30분이 걸려 기존 120초 목표와 약 10배 차이가 난다. 실제 강의 전사문으로 측정한 값이 아니다. 이 차이를 근거로 실제 사용 조건과 성공 기준을 사용자 인터뷰로 다시 정했다.

## 3. 시간 목표의 측정 구간

- **5분 노트:** 사용자가 녹음 종료를 누른 시점부터 5분 노트의 로컬 저장이 끝나 열람할 수 있는 시점까지다. 남은 전사, 구간 초안, 최종 통합, 검증, 저장을 포함한다. 녹음 중 미리 처리한 시간은 숨기지 않고 따로 기록한다.
- **적용 조건:** 녹음 중 미리 처리가 정상 동작한 녹음에 적용한다. 순차 모드나 배터리 절약 전환으로 미리 처리하지 못한 녹음은 목표 대상 외로 표시하고 실제 시간을 기록한다.
- **다시 요약:** 라이브러리에서 실행을 요청한 시점부터 새 노트 버전의 저장까지다. 저장된 전사문을 사용하며, 요청 후 수행하는 자료 처리를 포함한다.
- **정밀 정리:** 시간 목표 없이 진행률을 표시한다. 품질 검사를 통과한 경우에만 기본 보기로 바꾼다. 사용자가 수정한 노트는 자동 교체하지 않고 새 버전으로 알린다. 새 녹음이 시작되면 일시정지한다.
- **판정 전원 조건:** 시간 목표는 AC 전원 연결과 Windows 전원 모드 "최고 성능"에서 판정한다(2026-09-17 사용자 결정). 배터리 사용이나 다른 전원 모드의 결과는 참고로 기록하며 판정에 쓰지 않는다. 측정할 때는 전원 모드와 전원 연결 상태를 함께 기록한다.
- **품질 우선:** 품질 기준에 못 미친 결과는 시간과 관계없이 완성본으로 저장하지 않는다. 시간을 넘긴 결과는 '품질 통과·시간 실패'로 기록한다. 입력 생략, 옵션 은폐, 타이머 조작으로 목표를 맞추지 않는다.

## 4. Notion 연결 방식의 근거

2026-09-17 [Notion 공식 인증 문서](https://developers.notion.com/docs/authorization)를 확인했다. 공개 연동의 OAuth 토큰 교환은 `CLIENT_ID`와 `CLIENT_SECRET`을 사용한 HTTP Basic 인증을 요구하며, 비밀정보를 둘 수 없는 데스크톱 앱용 흐름(PKCE 등)은 안내되어 있지 않다. 운영 서버나 앱에 포함한 비밀정보 없이는 로그인 방식을 구현할 수 없으므로 제공하지 않는다.

내부 연결은 워크스페이스 소유자가 만들고, 설정 화면에서 토큰을 확인하며, 대상 페이지를 연결에 직접 공유해야 한다. 앱은 이 절차를 안내하고 토큰을 Windows 자격 증명 관리자에 저장한다. [Notion MCP 문서](https://developers.notion.com/docs/mcp)는 AI 도구를 클라이언트 예로 들 뿐 자체 앱에서 사용할 수 있는지 확인하지 못해 채택하지 않았다. API 요청 제한과 무과금 조건은 B 단계 착수 전에 공식 문서로 확인한다.

## 5. 위험과 후속 검증

- 생성 속도가 목표에 비해 부족할 수 있다. `llama-bench`로 스키마 제약 없는 속도를 먼저 측정하고 구간 크기·출력량을 조정한다. 그래도 미달이면 모델 변경 여부를 사용자와 결정한다. 1차 측정 결과는 [보고서](../validation/2026-09-17-llama-bench.md)에 기록했다(판정: infeasible_estimate, 추정. 녹음 종료 후 약 17~21% 초과, 측정 전원 모드 '최고의 전원 효율성'). '최고 성능' 모드 [재측정](../validation/2026-09-17-llama-bench-best-performance.md)에서는 feasible_estimate(녹음 종료 후 89~93초)였다. 이후 시간 목표는 AC·최고 성능 조건에서 판정하기로 결정했다(3절).
- RAM 16GB 노트북에서 STT와 LLM을 동시에 실행하지 못할 수 있다. 측정 후 녹음 중 전사만 수행하는 순차 모드를 제공한다. STT 단독 CPU 측정 결과는 [보고서](../validation/2026-09-18-stt-bench.md)에 기록했다(1차 후보 large-v3-turbo f16, 조각 RTF 중앙값 0.422, 코어 약 6개 사용, 추정). 동시 실행 측정([보고서](../validation/2026-09-23-concurrency.md))에서는 AC·"최고 성능"에서 동시 처리가 가능했고 16GB 예산도 여유 1,060MiB로 들어갔다. 전환 조건은 [0009](0009-concurrent-processing.md)에 정리했다.
- 녹음 중 처리로 배터리·발열·팬 소음과 온라인 강의 재생 끊김이 생길 수 있다. 전사 우선·배터리 절약 전환 규칙으로 대응하고 실측한다.
- 5분 노트는 앱 코드 병합 위주라 정밀 정리 버전보다 매끄럽지 않을 수 있다. 두 결과를 평가셋으로 비교한다.
- 수업 녹음은 교수자 방침을 따르도록 안내한다. 강의 녹음·전사를 평가·학습 데이터로 쓰기 전에 권한을 확인하고 저장소에 커밋하지 않는다.
- 무과금·약관 조건을 충족하는 외부 검색 공급자가 없으면 검색 기능을 보류하고 사유를 기록한다.
