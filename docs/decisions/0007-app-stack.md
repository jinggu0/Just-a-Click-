# 0007 — 앱 기술 구조 선택

- 날짜: 2026-09-17
- 상태: 기술 선택 확정. 개발 환경과 핵심 기능의 기술 검증 전
- 변경하는 결정: [0002](0002-runtime-candidates.md)의 데스크톱 셸 후보 비교
- 선택 기준: 사용자가 선택을 위임하면서 품질, UI/UX, 성능을 우선하도록 지정했다. 개발 속도는 차순위다.

## 1. 결정

**앱은 Tauri 2로 만들고 Rust 코어와 React·TypeScript 화면으로 구성한다.** 음성 인식과 LLM 추론은 앱과 분리된 별도 프로세스로 실행한다.

| 영역 | 선택 |
| --- | --- |
| 앱 셸 | Tauri 2, Windows WebView2 |
| 화면 | React + TypeScript |
| 코어 | Rust: 녹음, 작업 관리·진행률, 저장, 자료 분석, Notion 통신 |
| LLM | llama.cpp `llama-server`(Vulkan) 별도 프로세스, Qwen3-8B Q5_K_M([0004](0004-llm-selection.md)) |
| STT | whisper.cpp(Vulkan) 별도 프로세스. 모델은 한국어 평가 후 선정 |
| 저장 | 앱 데이터 폴더의 녹음 파일과 SQLite(메타데이터·전사·노트 버전·작업 상태). 검색은 SQLite FTS5 |
| 인증 정보 | Windows 자격 증명 관리자 |
| 개발·평가 도구 | 기존 Python 스크립트 유지. 요약 계약 검증 로직은 앱으로 옮긴다 |

추론 프로세스는 `127.0.0.1`에만 열고 임의 토큰으로 보호한다. 추론 오류나 GPU 장치 오류가 화면과 녹음을 멈추지 않도록 프로세스를 분리한다. 앱은 녹음 수집, STT, 요약 처리, 자료 분석, 저장, 검색 공급자, Notion 커넥터를 교체 가능한 경계로 나눈다.

## 2. 비교

| 후보 | 품질·UI/UX | 성능·자원 | 대가 |
| --- | --- | --- | --- |
| Tauri 2 + React/TS (선택) | 웹 기술로 화면 설계 자유도가 높고 애니메이션·동작 감소 설정 등을 표현하기 쉬움 | Rust 코어, 브라우저 엔진을 함께 배포하지 않고 시스템 WebView2 사용 | Rust·MSVC 빌드 도구 설치와 학습, 초기 착수 지연 가능 |
| C# .NET (WPF) | Windows 기본 컨트롤 중심이라 화면 표현이 웹보다 제한적 | 좋음. Windows 녹음·보안 저장소 연동이 안정적 | .NET SDK 설치, Python 코드 이식 |
| Python + PySide6 | Qt 기반. 세련된 화면 구성에 추가 노력이 필요 | 앱 시작 시간과 배포 용량 부담이 큼 | 가장 빠른 착수, 기존 코드 재사용 |

이 비교는 설계 판단이며 실측 결과가 아니다. RAM 16GB 노트북에서 8B 모델·STT와 함께 실행하므로 앱 자체의 메모리 사용량을 실제로 측정한다.

## 3. 채택 전 기술 검증

다음 항목이 실패하면 해당 영역의 대안을 검토한다. 녹음이나 화면 기반이 성립하지 않으면 C# .NET 대안으로 다시 결정한다.

1. Rust·MSVC 빌드 도구와 Tauri 2의 Windows 빌드, Windows 10을 포함한 WebView2 동작.
2. 마이크와 시스템 소리(WASAPI loopback)의 장시간 녹음, 일시정지, 구간 파일 저장, 절전 방지.
3. llama.cpp·whisper.cpp 프로세스의 시작·종료·장애 복구와 작업 취소.
4. SQLite FTS5의 한국어 부분 일치 검색. trigram 토크나이저를 우선 후보로 둔다.
5. Windows 자격 증명 관리자의 토큰 저장·삭제.
6. B 단계 전: PDF 텍스트·페이지 추출과 페이지 렌더링, PPTX 텍스트·슬라이드 위치 추출.

각 라이브러리는 도입 시점에 공식 저장소의 라이선스와 유지 상태를 확인해 기록한다. 라이브러리 버전은 아직 고정하지 않았다.
