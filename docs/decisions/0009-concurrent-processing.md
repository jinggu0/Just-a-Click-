# 0009 — 녹음 중 동시 처리와 순차 모드 전환 조건

- 날짜: 2026-09-23
- 상태: 초안. 공개 낭독 음성을 녹음처럼 재현한 측정 기준이며 실제 강의·배터리·16GB 실기기 검증 전이다
- 근거 측정: [동시 실행 측정 보고서](../validation/2026-09-23-concurrency.md), [측정 설계](../superpowers/specs/2026-09-19-concurrency-benchmark-design.md)
- 관련 결정: [0006](0006-lecture-first-product-scope.md) 제품 범위·시간 목표, [0008](0008-stt-candidate.md) STT 후보, [0004](0004-llm-selection.md) 기준 LLM

## 1. 결정

**녹음 중에는 전사와 5분 창 구간 초안을 함께 실행한다.** 기준 노트북에서 AC 전원·"최고 성능" 조건이면 전사가 실시간을 따라가면서 초안이 창의 7%만 쓴다(추정). 아래 실행 설정과 전환 조건을 A 단계 기준값으로 둔다.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| STT | whisper.cpp `b5130` OpenBLAS 빌드, large-v3-turbo f16, 8스레드, `-nt` | [0008](0008-stt-candidate.md) |
| LLM | llama.cpp `b10994` Vulkan, Qwen3-8B Q5_K_M, 2스레드, 전 계층 GPU | 스레드 배분 비교에서 LLM 2스레드가 전사·초안 모두 유리 |
| LLM 컨텍스트 | 8,192 | 16,384는 GPU 공유 메모리 9,157MiB로 16GB 기기 한도(약 7,838MiB)를 넘는다 |
| 프롬프트 캐시 | 끔(`--cache-ram 0`) | 기본값 8,192MiB에서는 초안 1건마다 약 180MiB가 쌓이고 생성이 32% 느렸다 |
| 창 크기·출력 | 음성 5분마다 초안 1건, 출력 300토큰 | [0006](0006-lecture-first-product-scope.md) 가정 |
| 우선순위 | 녹음 저장과 전사가 LLM 미리 처리보다 우선 | PRD 처리 원칙 |

## 2. 순차 모드·미리 처리 중단 조건

다음 중 하나라도 해당하면 LLM 미리 처리를 멈추고 녹음 중 전사만 수행한다(순차 모드). 화면과 기록에 전환 사실을 표시하고, 남은 창은 녹음 종료 후 처리한다.

| 조건 | 임계값 | 근거 |
| --- | --- | --- |
| 전사 지연 | 60초 초과가 이어질 때 | 판정 측정의 최대 지연은 14.8초, 효율 모드에서는 530초까지 쌓였다 |
| 전사 대기열 | 처리 대기 조각이 2개 이상일 때 | 판정 측정의 대기 시간은 최대 7초였다 |
| 전원 모드 | "최고 성능"이 아닐 때 | 효율 모드에서 동시 처리가 실시간을 따라가지 못했다(지연 중앙값 198초) |
| 전원 연결 | 배터리 사용 또는 배터리 절약일 때 | 배터리 조건은 미측정이며 효율 모드 결과로 위험이 확인됐다 |
| 가용 메모리 | 1.5GiB 미만일 때 | 16GB 기기 예산 여유가 1,060MiB로 크지 않다 |

전환 후에는 전사 지연이 30초 아래로 내려가고 전원 조건을 만족할 때만 미리 처리를 다시 시작한다. 시간 목표(녹음 종료 후 5분) 대상이 아니게 되면 그 사실을 기록하고 표시한다([0006](0006-lecture-first-product-scope.md) 3절).

## 3. 16GB 노트북 판단

기준 노트북(RAM 31.5GiB)에서 측정한 최대 사용량으로 추정했다. 전용 메모리와 GPU 공유 메모리는 Vulkan 할당이 양쪽에 잡혀 큰 값만 한 번 셌다.

| 항목 | 측정값 | 16GB 기기 기준 |
| --- | --- | --- |
| STT 조각 최대 전용 메모리 | 3,363MiB | - |
| llama-server 전용 메모리 | 7,557MiB | - |
| 합계 | 10,921MiB | 예산 11,981MiB(15.7GiB − OS·앱 4GiB 가정) |
| GPU 공유 메모리 | 7,367MiB | 한도 약 7,838MiB(물리 메모리의 절반) |

여유가 1GiB 남짓이라 다른 앱이 많으면 부족할 수 있다. 실제 16GB 기기에서 같은 도구로 확인하기 전에는 "가능(추정)"으로만 둔다. 모델을 상주시키는 앱 구조에서는 STT 프로세스를 유지해 적재를 줄이고, 필요하면 컨텍스트를 4,096으로 낮춘다(GPU 공유 6,504MiB).

## 4. 재검토 조건

- 배터리 조건 측정에서 미리 처리가 불가능하다고 확인될 때(전환 조건을 규칙으로 확정).
- 실제 강의 녹음에서 창 입력 토큰이 가정(1,000~2,000토큰)보다 크게 늘어날 때.
- 16GB 실기기에서 메모리가 부족할 때(컨텍스트 축소, 순차 모드 기본값 검토).
- llama.cpp 빌드를 올려 프롬프트 캐시 동작이나 생성 속도가 달라질 때.
- 앱에서 오디오 캡처·점진 저장·화면 처리 부하를 더한 측정 결과가 나올 때.
