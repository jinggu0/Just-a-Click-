# 로컬 STT 후보 측정 설계

- 날짜: 2026-09-17
- 상태: 사용자 승인 설계. 구현·측정 전
- 대상 작업: [로드맵](../../ROADMAP.md) M0 남은 작업 2 — 로컬 STT 후보의 한국어 품질, 실시간 대비 속도, 라이선스·배포 조건 확인
- 판정 조건: AC 전원·Windows 전원 모드 "최고 성능"([결정 0006](../../decisions/0006-lecture-first-product-scope.md) 3절)

## 1. 목적과 범위

whisper.cpp 다국어 모델을 기준 노트북의 CPU에서 실행해 다음을 1차 판정한다.

1. 녹음 중 30초 조각을 실시간으로 전사할 수 있는가.
2. 모델 크기·양자화에 따라 한국어 전사 품질이 얼마나 달라지는가.
3. A 단계의 1차 STT 후보를 어떤 모델로 둘 것인가.

범위 밖: GPU(Vulkan)·NPU(OpenVINO) 실행, STT·LLM 동시 실행(M0 남은 작업 3), 실제 강의 녹음, 전공 용어 정확도, 화자 분리, 음성 구간 검출(VAD), 앱 연동.

## 2. 사용자 결정 사항

| 항목 | 결정 |
| --- | --- |
| 실행 방식 | 공식 배포된 whisper.cpp Windows x64 CPU·OpenBLAS 빌드로 먼저 측정한다. Vulkan 빌드는 공식 배포본이 없으며, CPU가 부족하면 GPU·NPU 경로를 별도로 검토한다 |
| 평가 음성 | 공개 데이터와 본인 강의 녹음을 함께 쓴다. 현재 강의 녹음이 없으므로 공개 데이터로 먼저 측정하고, 강의 녹음은 확보 후 같은 도구로 추가한다 |
| 모델 조합 | 품질 최우선 세트: small q5_1, medium q5_0, large-v3-turbo q5_0·f16, large-v3 q5_0·f16 |
| 다운로드 | 위 모델, whisper.cpp CPU·OpenBLAS 빌드, FLEURS 한국어 test의 다운로드에 동의 |
| 측정 방식 | 30초 조각마다 `whisper-cli`를 실행한다. `whisper-server`는 인증·출처 제한이 없고 모델 적재 경로(`/load`)가 있어 사용하지 않는다 |
| 디코딩 방식 | 실행 확인에서 기본(타임스탬프) 방식이 조각 뒷부분을 자주 누락했다. small 모델 조각 6개 중 5개에서 누락이 있었고, 조각 002~006의 CER은 0.419로 `-nt`의 0.227보다 높았다. `-nt`에서도 2개 조각은 뒷부분이 빠졌다. 실행 설정 선정과 모델 비교는 `-nt`로 하고, CER이 가장 낮은 2개 모델만 타임스탬프 방식으로 다시 측정해 누락 위험을 기록한다(사용자 결정) |

## 3. 판정 기준

모든 판정은 추정이며 앱의 실제 지연시간이나 출시 품질 판정이 아니다.

- **속도:** 조각 처리 비율 RTF = (whisper 전체 처리 시간 − 모델 로딩 시간) ÷ 조각 길이. 중앙값 ≤ 0.5이고 95번째 백분위 ≤ 0.8이면 "녹음 중 CPU 실시간 처리 가능(추정)"으로 본다. STT가 녹음 시간의 절반 이하를 써야 LLM 구간 초안(최고 성능 모드 점유율 약 0.08~0.09)·녹음 저장·화면 처리와 병행할 여유가 생긴다는 설계 판단이다. 기준을 넘으면 GPU·NPU 경로 검토를 사용자 결정으로 올린다.
- **백분위:** 95번째 백분위는 조각 RTF를 오름차순으로 정렬한 뒤 최근접 순위(ceil(0.95 × n)번째 값)로 구한다.
- **품질:** 조각 전체의 편집 수 합을 정답 글자 수 합으로 나눈 글자 오류율(CER)을 모델별로 기록한다. 정답과 출력 모두 NFKC로 정규화하고, 영문을 소문자로 바꾸고, 공백과 문장부호를 제거한 뒤 편집 거리로 계산한다. 원문의 괄호 속 원어처럼 화자가 읽지 않았을 수 있는 영문 표기를 고려해, 한글 음절만 남긴 CER(`cer_hangul`)도 함께 기록한다. 합격 임계값은 강의 평가셋 확보 후 정한다.
- **1차 후보 선정:** 속도 기준을 통과한 모델 중 `cer`이 가장 낮은 모델을 고른다. `cer` 차이가 0.5%p 이내면 RTF 중앙값이 낮은 모델을 고른다. 통과 모델이 없으면 후보를 정하지 않고 사용자 결정으로 넘긴다.
- **전체 RTF:** 조각 길이가 13~30초로 다르고 Whisper는 짧은 조각도 30초 창으로 처리하므로, 조각별 RTF는 30초 조각보다 크게 나온다(보수적). 전체 처리 시간 ÷ 전체 음성 길이(`rtf_total`)도 함께 기록한다.
- **이상 의심:** 조각 CER이 50%를 넘거나(누락 포함) 정규화 출력 길이가 정답의 2배 이상이면(반복·환각) 표시하고 보고서에 조각 번호를 남긴다.
- **환경 기록:** 시작·종료 시 전원 모드(레지스트리 읽기), AC 연결, 배터리 절약, 전체 CPU 사용률, 온도, 빌드·스레드·디코딩 설정을 기록한다.

### 공개 데이터

[Google FLEURS](https://huggingface.co/datasets/google/fleurs) 한국어 test(CC BY 4.0, revision `70bb2e84b976b7e960aa89f1c648e09c59f894dd`)를 쓴다.

| `data/ko_kr/test.tsv` | 211,844 bytes | `cf2f7c8765f6203e3c46ef620d5e936d3f331b6e8865455557777dd1347517f5` |
| `data/ko_kr/audio/test.tar.gz` | 214,425,558 bytes | `3489e529f2aad18d3357b746c5f955941d258b79dc60d8a102d5bced2a223184` |

2026-09-17 확인 결과 전사 파일은 382줄이며 열은 번호, 파일명, 원문 전사, 정규화 전사, 글자 분해, 샘플 수(16kHz), 성별 순이다. 고유 문장은 270개(문장당 최대 3개 녹음), 전체 1.33시간, 평균 12.6초다.

조각 구성 규칙:

1. 같은 문장 번호의 녹음은 파일명이 사전순으로 가장 앞선 1개만 쓴다.
2. 문장 번호의 숫자 순서대로 이어 붙이고, 문장 사이에 0.5초 무음을 넣는다.
3. 다음 문장을 붙이면 30.0초를 넘을 때 조각을 닫는다. 30초를 넘는 단일 문장은 쓰지 않는다.
4. 조각 60개를 만들면 멈춘다. 실제 구성 결과는 문장 106개, 총 1,406초(약 23분), 조각당 13.2~29.9초다.
5. 조각의 정답은 포함된 문장의 정규화 전사(4번째 열)를 공백으로 이어 붙인 것이다.

조각 목록(문장 번호, 파일명, 샘플 수, 정답)과 출처·라이선스 표기는 `evaluation/fixtures/stt-fleurs-ko-v1.json`으로 커밋한다. 음성 원본은 `downloads/`, 조각 WAV는 `artifacts/`에 두어 Git에서 제외한다.

### 강의 녹음(추후)

교수자의 녹음 허락이 있는 본인 강의 녹음을 `evaluation/private/`(Git 제외)에 두고 같은 조각 목록 형식으로 측정한다. 정답 전사는 사용자가 작성하며, 가장 좋은 모델의 출력을 고쳐 만든 경우 편향 가능성을 보고서에 적는다. 강의 음성·전사는 커밋하지 않고 지표만 남긴다.

### 한계

낭독 음성이고, 문장을 이어 붙여 화자가 바뀌며, 전공 용어와 강의실 잡음이 없다. 숫자·원어 표기는 정답과 읽은 방식이 다를 수 있다.

## 5. 실행 흐름

측정은 타임스탬프 비교를 포함해 약 1.5~2.5시간으로 추정하며 이 단계에서만 노트북을 쓰지 않아야 한다.

1. **사전 점검:** 모델·빌드 파일의 크기·해시, 조각 WAV, AC 연결, 다른 `llama-*`·`whisper-*` 프로세스를 확인한다. AC가 아니거나 다른 추론 프로세스가 있으면 시작하지 않는다. 전원 모드가 "최고 성능"이 아니면 경고하고 기록한다.
2. **실행 설정 선정(screen):** large-v3-turbo q5_0으로 CPU·OpenBLAS 빌드 × 4·8스레드를 조각 10개에 `-nt`로 실행하고, 모든 조각을 마친 조합 중 RTF 중앙값이 가장 낮은 조합을 고른다.
3. **모델 비교(models):** 고른 조합과 `-nt`로 small → medium → large-v3-turbo q5_0 → large-v3-turbo f16 → large-v3 q5_0 → large-v3 f16 순서로 조각 60개 전체를 실행한다.
4. **타임스탬프 비교(timestamp_check):** 판정 가능한 모델 중 CER이 가장 낮은 2개를 같은 설정의 타임스탬프 방식으로 조각 60개에 다시 실행한다. 선정 규칙에는 쓰지 않고 누락 위험의 근거로 기록한다.
5. **요약:** 실행 묶음마다 `cer`, `cer_hangul`, RTF 중앙값·95번째 백분위·최대·전체, 모델 로딩 시간 중앙값, 온도 대체 디코딩 횟수, 실패·이상 의심 조각과 선정 결과를 기록한다.

`whisper-cli`는 조각마다 `-m <모델> -f <조각> -l ko -t <스레드> -oj -of <출력 경로>`로 실행하고, 비교 실행에는 `-nt`를 붙인다. 표준 오류의 시간 기록(`load time`, `total time`)과 처리 조건 줄(스레드·빔·언어)을 읽는다. 빌드 b5130의 기본 디코딩은 빔 5·후보 5이며 온도 대체를 사용한다(실행 확인 결과). 시간 기록을 숨기는 출력 억제 옵션(`-np`)은 쓰지 않는다.

`--models`로 일부 모델만 고르거나 `--chunks`로 조각 수를 줄인 실행은 진단용으로 보고 결과를 `artifacts/`에만 남긴다.

## 7. 오류 처리

- 조각별 시간 제한 300초. 시간 초과·비정상 종료는 기록하고 다음 조각을 계속한다. 모델 단위로 실패 조각이 10%를 넘으면 해당 모델의 판정을 "판정 불가"로 둔다.
- 조각을 처리할 때마다 요약을 `artifacts/`에 다시 저장해 중간에 멈춰도 결과를 보존한다. 결과 파일은 덮어쓰지 않는다.
- 파일 크기·해시 불일치, 누락된 조각 WAV가 있으면 측정을 시작하지 않는다.
- 로그·요약에 저장소 경로와 사용자 경로를 남기지 않는다.
- 전원 설정·드라이버를 바꾸지 않는다. 절전 방지는 측정 프로세스 실행 중에만 요청한다.

## 8. 검증

- 단위 테스트: tsv 해석과 문장 선택, 조각 경계·무음 길이·30초 초과 문장 제외, 부동소수점·16비트 WAV 읽기, 정규화와 두 CER, whisper 시간 기록 해석(로딩·전체 시간·처리 조건), 명령 구성(`-nt` 기본), RTF 백분위, 선정 규칙(속도 통과·0.5%p 규칙·통과 모델 없음), 상위 2개 선택, 이상 의심 판정, 전원 모드 GUID 해석, zip 경로 이탈 차단. 기존 테스트도 계속 통과한다.
- 실제 실행 확인: 전체 측정 전에 small q5_1로 조각 2개를 진단 실행해 JSON 출력과 시간 기록 형식을 확인한다(설계 단계에서 조각 6개로 형식과 누락 현상을 확인했다).
- 측정 후 보고서를 작성하고 로드맵 M0 남은 작업 2와 STT 후보 결정 기록 초안에 반영한다.

## 9. 후속 작업

- 강의 녹음 확보 후 같은 도구로 전공 용어·잡음·긴 녹음을 평가한다.
- 1차 후보로 STT·LLM 동시 실행(M0 남은 작업 3)을 측정한다.
- CPU 속도가 부족하면 Vulkan 빌드나 OpenVINO(NPU) 경로를 사용자 결정으로 검토한다.
