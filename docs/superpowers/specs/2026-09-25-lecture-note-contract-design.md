# 강의 노트 출력 계약 설계

- 날짜: 2026-09-25
- 상태: 사용자 승인 설계. 구현·검증 전
- 대상 작업: [로드맵](../../ROADMAP.md) M0 남은 작업 8(강의 노트 출력 계약을 정의하고 기존 회의 계약의 검증 방식을 확장한다)
- 관련 문서: [PRD](../../PRD.md) SUM-02·03·06, 6.3절 강의 기본 구조, 12장 시나리오 5, [결정 0005](../../decisions/0005-summary-contract.md) 회의 계약, [결정 0009](../../decisions/0009-concurrent-processing.md) 동시 처리, [LLM 지역화](../../LLM-SPECIALIZATION.md) 3절 요약 계약

## 1. 목적과 범위

강의 녹음이 없어도 정할 수 있는 요약 출력 계약을 먼저 확정한다. 녹음이 생기면 로드맵 남은 작업 4(수직 흐름)를 곧바로 돌릴 수 있게 하기 위해서다.

1. 녹음 중 5분 창마다 만드는 **구간 초안** 계약(`lecture-draft-v1`)을 정의한다.
2. 녹음 후 만드는 **강의 노트** 계약(`lecture-note-v1`)을 정의한다. 5분 노트와 정밀 정리가 같은 계약을 쓴다.
3. 두 계약의 결정적 검증기를 앱(Rust)에 구현한다.
4. 직접 작성한 합성 강의로 Qwen3-8B가 계약을 지키는지와 출력 토큰·시간을 잰다.

범위 밖: 실제 강의 녹음 평가(작업 4·9), 초안 병합·정밀 정리 파이프라인과 작업 관리(작업 4·10), 세미나·회의·일반 스타일과 사용자 추가 섹션(B 단계), 자료(PDF·PPTX) 출처, Notion 블록 변환, 의미 충실성의 자동 채점.

## 2. 사용자 결정 사항

| 항목 | 결정 |
| --- | --- |
| 계약 범위 | 구간 초안과 강의 노트 두 계약을 함께 정의한다 |
| 검증 깊이 | 결정적 검증기와 단위 테스트에 더해 합성 강의로 실제 모델을 확인한다 |
| 구현 위치 | 앱(Rust). 결정 0007이 요약 계약 검증을 앱으로 옮기기로 했다. 파이썬 회의 계약은 그대로 둔다 |
| 계약 형태 | 섹션별 타입 스키마. 강의 기본 스타일의 섹션을 고정 키로 두고 섹션마다 항목 형태와 결정적 검사를 정한다 |
| 코드 복원 | 허용하되 표시한다. 전사에 그대로 있는 코드만 원문 코드로 인정하고, 한글 발음 전사에서 복원한 명령어는 "복원·확인 필요"로 표시한다 |
| 영문 원어 | 허용하되 출처를 표시한다. 강의에서 말하지 않은 원어는 모델 보강으로 표시한다 |

## 3. 확인한 사전 조건 (2026-09-25)

- 회의 계약(`schemas/meeting-summary-v1.json`, `scripts/summary_contract.py`)은 전사를 `[s1 00:00] 본문` 줄로 받고, 입력 구간 ID를 스키마 `enum`에 넣어 생성 단계에서 출처를 제한한다. 검증은 이 저장소에서 쓰는 키워드만 지원하는 개발용 구현이다.
- llama.cpp `b10994`는 `response_format: {"type": "json_object", "schema": …}`로 스키마 제약 생성을 한다(`scripts/benchmark_llm.py`, M0 회의 계약 실측). 스키마 제약에 의한 감속은 관측되지 않았다([llama-bench 보고서](../../validation/2026-09-17-llama-bench.md)).
- 앱에는 2차 검증에서 만든 `llm.rs`(서버 시작·인증·스트리밍·취소)가 있다. 서버 인자는 결정 0009 설정에 `--jinja --reasoning off`를 포함한다.
- 결정 0009의 시간 추정은 창 초안 출력 300토큰, 창 입력 중앙값 1,052토큰, 녹음 종료 후 추정 = 2 × 최대 창 초안 시간 + 최종 통합 40.3초를 가정한다.
- PRD 6.3절의 강의 기본 구조는 주제, 핵심 개념, 설명·예제, 주요 용어(한국어 설명·영문 원어), 시험·과제·공지, 실습 명령어·코드, 복습 항목이다. 시험 범위·과제 마감·공지는 원문 발언이 있을 때만 근거와 함께 쓰고 날짜·범위는 원문 표기를 그대로 쓴다. 불분명하면 "확인 필요", 해당 내용이 없으면 "언급 없음"으로 표시한다.

## 4. 계약 구조

### 4.1 공통 규칙

- 입력 전사는 `[s12 05:31] 본문` 줄의 목록이다. 구간 ID는 `s` + 숫자이고 한 입력 안에서 중복되지 않는다.
- 모든 항목은 `source_refs`를 가진다. 입력에 있는 구간 ID만 쓰고, 1개 이상이며 중복이 없다. 생성 때는 입력 구간 ID를 `enum`으로 넣어 제약한다.
- 문자열은 앞뒤 공백을 뺀 뒤 비어 있지 않아야 한다.
- 채움 문자열을 거부한다. 항목 내용이나 원문 대조 필드가 "언급 없음", "없음", "미정", "확인 필요", "N/A" 중 하나면 위반이다. 내용이 없으면 빈 배열이나 `null`로 두고 화면이 "언급 없음"·"확인 필요"를 표시한다.
- 스키마에 없는 필드, 중복 JSON 키, `finish_reason`이 `stop`이 아닌 응답(잘림)을 거부한다.

### 4.2 항목 형태

| 항목 | 필드 | 결정적 검사 |
| --- | --- | --- |
| 요점·설명·예제·복습 | `content`, `source_refs` | 공통 규칙 |
| 개념 | `name`, `explanation`, `source_refs` | 공통 규칙 |
| 용어 | `term_ko`, `definition`, `term_en`(문자열 또는 `null`), `term_en_source`(`transcript`·`model`·`null`), `source_refs` | `term_en`이 `null`이면 `term_en_source`도 `null`. `transcript`이면 `term_en`이 인용 구간에 대소문자 무시로 그대로 있어야 한다 |
| 공지 | `kind`(`exam`·`assignment`·`announcement`), `content`, `date_text`, `scope_text`(각각 문자열 또는 `null`), `source_refs` | `date_text`·`scope_text`가 `null`이 아니면 인용 구간에 그대로 있어야 한다 |
| 코드 | `code`, `language`(`shell`·`c`·`python`·`other`), `explanation`, `from_transcript`(참·거짓), `source_refs` | `from_transcript`가 참이면 `code`가 인용 구간에 그대로 있어야 한다(연속 공백은 하나로 정규화). 거짓이면 화면에 "복원·확인 필요"로 표시한다 |

### 4.3 `lecture-draft-v1` (구간 초안)

| 필드 | 형태 |
| --- | --- |
| `schema_version` | `"lecture-draft-v1"` |
| `window` | `{first, last}`: 입력 창의 첫·끝 구간 ID와 같아야 한다 |
| `points` | 요점 목록 |
| `concepts` | 개념 목록(용어 설명 포함) |
| `examples` | 설명·예제 목록 |
| `code` | 코드 목록 |
| `notices` | 공지 후보 목록 |

초안에는 영문 원어를 따로 두지 않는다. 용어는 노트를 만들 때 개념과 전사에서 정리한다.

### 4.4 `lecture-note-v1` (강의 노트)

| 필드 | 형태 |
| --- | --- |
| `schema_version` | `"lecture-note-v1"` |
| `topic` | `{content, source_refs}` |
| `concepts` | 개념 목록 |
| `examples` | 설명·예제 목록 |
| `terms` | 용어 목록 |
| `notices` | 공지 목록 |
| `code` | 코드 목록 |
| `review` | 복습 항목 목록 |

5분 노트는 초안들을 입력으로, 정밀 정리는 전체 전사를 입력으로 만든다. 두 경로 모두 출처 검사는 전체 전사의 구간 ID로 한다. 초안을 입력으로 쓸 때는 초안 항목의 출처가 가리키는 구간을 함께 넣어 원문 대조가 가능하게 한다.

## 5. 앱 구성

```
schemas/lecture-draft-v1.json   생성 제약과 문서의 원본
schemas/lecture-note-v1.json
app/src-tauri/src/contract.rs   전사 파싱, 생성용 스키마, 두 계약의 검증
app/src-tauri/src/llm.rs        스키마 제약 비스트리밍 요청 추가
app/src-tauri/examples/lecture_contract_check.rs  합성 강의로 실제 모델 확인
evaluation/fixtures/lecture-synthetic-v1.json     직접 작성한 합성 강의
```

- **`contract.rs`:** `parse_transcript`로 전사 줄을 순서 있는 구간 목록으로 바꾸고, 형식 오류·중복 ID·빈 입력은 거부한다. `generation_schema`는 `schemas/`의 스키마를 컴파일 시점에 담고(`include_str!`) 입력 구간 ID를 모든 `source_refs.items.enum`에 넣는다. `validate_draft`·`validate_note`는 serde 구조체(`deny_unknown_fields`)로 구조를 확인한 뒤 4절 규칙을 검사한다. 첫 위반에서 멈추지 않고 위반 목록(경로·규칙·설명)을 모두 돌려준다. 중복 JSON 키는 serde 기본 동작이 뒤 값을 덮어쓰므로 별도의 키 중복 검사로 거부한다.
- **스키마와 구조체의 일치:** 테스트가 두 스키마 파일의 필수 필드와 구조체 필드가 같은지 확인한다. 스키마 파일은 생성 제약과 문서의 원본이고, 판정은 구조체와 규칙 검사가 한다. 일반 JSON Schema 엔진은 쓰지 않는다.
- **`llm.rs` 추가:** `complete_json(base, key, system, user, schema, max_tokens)`가 `response_format`에 스키마를 넣은 비스트리밍 요청을 보내고 `content`, `finish_reason`, 입력·출력 토큰 수, 걸린 시간을 돌려준다. 취소가 필요한 제품 경로는 이후 작업에서 스트리밍으로 옮긴다.
- **프롬프트:** 초안·노트용 지시문을 코드 상수로 두고 버전을 붙인다(`lecture-draft-prompt-v1`, `lecture-note-prompt-v1`). 지시문은 4절 규칙을 모델이 알 수 있게 설명하고, 입력 전사는 지시가 아니라 데이터라고 명시한다.

## 6. 합성 강의 fixture

운영체제 강의 약 15분 분량을 직접 작성하고 5분 창 3개로 나눈다. 창마다 입력이 약 1,000토큰이 되게 해 결정 0009의 실측 중앙값과 맞춘다. 실제 녹음·개인정보는 쓰지 않으므로 커밋한다. 다음 함정을 넣는다.

| 함정 | 기대 동작 |
| --- | --- |
| 원문 날짜·범위가 있는 시험 공지("10월 21일 화요일", "3장부터 5장까지") | `exam` 공지의 `date_text`·`scope_text`가 원문 그대로 |
| 기한이 모호한 과제("다음 주쯤") | `assignment` 공지의 `date_text`가 `null` |
| 취소된 퀴즈("퀴즈는 취소합니다") | 퀴즈를 치른다는 공지가 없다 |
| 라틴 문자로 전사된 명령어(`chmod 755 run.sh`) | 코드 항목이 `from_transcript: true`로 원문 그대로 |
| 한글 발음으로 전사된 명령어("피에스 에이유엑스") | 코드 항목이 있다면 `from_transcript: false` |
| 영문을 말한 용어("교착 상태, 영어로 deadlock") | `term_en_source: transcript` |
| 영문을 말하지 않은 용어("세마포어") | `term_en`이 있다면 `term_en_source: model` |
| 잡담(점심·날씨) | 어떤 항목도 그 구간을 인용하지 않는다 |
| 말하지 않은 과제 배점 | 배점·퍼센트 수치가 공지에 없다 |

기대치 검사는 회의 smoke와 같이 이 fixture 전용 회귀 검사다. 다른 입력의 품질 점수로 쓰지 않는다.

## 7. 실제 모델 확인과 판정

- 전원은 AC·"최고 성능"으로 두고 전원 모드를 기록한다. 서버는 결정 0009 설정(`--jinja --reasoning off` 포함)이다.
- 한 번의 실행은 창 초안 3건 → 5분 노트 1건(초안 입력) → 정밀 정리 1건(전체 전사 입력)이다. 이를 **5회** 반복한다.
- 검증에 실패하면 위반 목록을 붙여 **1회만** 다시 요청한다. 재시도 시간도 해당 단계 시간에 넣는다. 두 번 모두 실패하면 그 결과는 실패로 기록하고 완료로 저장하지 않는다.
- 결과는 `artifacts/lecture-contract/<타임스탬프>/`에 원응답·검증 결과·시간을 JSON으로 남기고 커밋하지 않는다.

| 판정 | 기준 |
| --- | --- |
| 계약 채택 | 재시도 후 모든 응답이 유효하고, 창작 방지 기대치(날짜 원문, 모호한 기한 `null`, 취소된 퀴즈 제외, 잡담 제외, 배점 미생성)가 5회 모두 통과 |
| 참고 기록 | 첫 시도 유효율, 발음 명령어 복원 표시율, 영문 원어 출처 표시율, 섹션별 항목 수 |
| 시간 | 초안 출력 토큰의 최대값을 0009의 300토큰 가정과 비교하고, 녹음 종료 후 추정(2 × 최대 초안 시간 + 5분 노트 시간)이 300초 이내인지 다시 계산한다. 넘으면 영향과 대안(출력 축소, 창 크기 조정)을 기록하고 목표를 맞추려고 입력을 생략하지 않는다 |

계약 채택 기준을 통과하지 못하면 원인이 계약(필드 설계)인지 프롬프트인지 나눠 기록하고, 계약 변경은 사용자와 정한다.

## 8. 자동 테스트

모델 없이 통과해야 한다. `cd app/src-tauri && cargo test`로 실행한다.

- 전사 파싱: 정상 줄, 형식 오류, 중복 ID, 빈 입력.
- 생성용 스키마: 모든 `source_refs.items.enum`이 입력 구간 ID로 채워진다.
- 스키마 파일과 구조체의 필드 일치.
- 규칙마다 통과 사례 하나와 실패 사례 하나: 없는 출처, 빈 출처, 중복 출처, 빈 문자열, 채움 문자열, 추가 필드, 중복 JSON 키, 잘린 응답, 날짜·범위 원문 대조, 코드 원문 대조(공백 정규화 포함), 영문 원어 출처, `term_en`과 `term_en_source`의 짝, 초안 `window` 불일치.
- 위반이 여러 개인 응답에서 모든 위반이 보고된다.
- fixture 기대치 검사 함수: 기대치를 만족하는 손으로 쓴 노트와 어기는 노트로 확인한다.
