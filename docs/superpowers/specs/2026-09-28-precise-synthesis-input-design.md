# 정밀 정리 합성 입력 줄이기 설계

- 날짜: 2026-09-28
- 상태: 사용자 승인 설계. 구현·검증 전
- 대상: [결정 0010](../../decisions/0010-lecture-note-contract.md) 7절의 합성 호출(`lecture-precise-synthesis-v1`)
- 근거: [정밀 정리 창별 호출 실측](../../validation/2026-09-28-precise-note-by-window.md) 4절

## 1. 문제

합성 호출은 병합된 개념마다 `- 이름 [출처]: 설명`을 받아 주제와 복습을 쓴다. 측정에서 개념 한 줄은 약 53토큰이었고 고정 부분은 약 340토큰이었다. 병합 뒤 창당 개념은 5.8개였으므로, 창 30개(2.5시간) 강의에서 개념이 100~170개면 입력은 약 5,600~9,300토큰이 된다. 최대 출력 2,048토큰을 더하면 컨텍스트 8,192를 넘는다.

설명을 첫 문장만 남기는 방법은 효과가 거의 없다. 설명이 대부분 한 문장이어서 개념당 48토큰이 된다. 이름과 출처만 남기면 개념당 약 11토큰이다. 이 경우 170개는 약 2,200토큰, 300개(4시간 이상)는 약 3,700토큰이다(추정, 측정 문자 수 × 0.64).

## 2. 사용자 결정

| 질문 | 결정 |
| --- | --- |
| 줄이는 방법 | 개념마다 이름과 출처만 넘긴다. 입력 크기는 호출 전에 검사한다 |

## 3. 설계

- **입력 형식:** `synthesis_input`은 개념마다 `- 이름 [s1, s13]` 한 줄을 쓰고 설명은 넣지 않는다.
- **프롬프트:** `lecture-precise-synthesis-prompt-v2`. "개념 이름과 인용 구간 목록을 읽고 주제와 복습 항목을 쓴다"로 바꾼다. 나머지 규칙과 스키마(`lecture-precise-synthesis-v1`)는 그대로다.
- **인용 제한:** 지금처럼 합친 노트가 이미 인용한 구간만 인용할 수 있다.
- **크기 검사:** 호출 전에 llama-server `/tokenize`로 시스템 프롬프트와 사용자 입력의 토큰 수를 센다. 채팅 템플릿 몫 64토큰과 최대 출력을 더해 컨텍스트를 넘으면 호출하지 않는다. 입력을 자르지 않고 `input_too_large`로 실패를 기록한다. 이 경우 정밀 정리는 완료로 저장하지 않으며 5분 노트가 그대로 남는다(0006: 정밀 정리는 품질 검사를 통과해야 기본 보기로 바뀐다).
- **앱 구성:**
  - `llm.rs`: `count_tokens(base, key, text) -> Result<usize, String>`. 요청 본문과 응답 읽기는 순수 함수로 두고 단위 테스트한다.
  - `lecture_merge.rs`: `synthesis_input` 형식을 바꾸고 `fits_context(prompt_tokens, max_tokens, context_tokens) -> bool`을 둔다.
  - 하네스: 합성 호출 전에 크기를 검사하고, 결과를 호출 기록에 남긴다.

## 4. 검증

전체 하네스를 다시 돌리지 않고 합성 호출만 재생한다(예제 `precise_synthesis_check`).

1. **품질 비교:** 정밀 정리 측정 1·2(`artifacts/lecture-contract-v2/precise-1/`, `precise/`)의 노트 10건에서 개념·예제·용어를 읽어 병합 결과를 되살린다. 이름·출처 입력으로 합성을 다시 돌린 뒤, 설명이 들어간 기존 주제·복습과 나란히 비교한다.
2. **규모 시험:** 10건의 개념을 이어 붙인 목록(약 160개, 2.5시간 규모)과 그 두 배(약 320개)로 합성을 돌려 실제 입력 토큰·시간·채택 여부를 본다. 두 배 목록은 같은 이름이 되풀이되므로 크기 확인용이다.
3. **크기 검사:** 예산을 넘는 입력(설명을 넣은 320개)을 만들어 호출 없이 `input_too_large`로 기록되는지 본다.

| 기준 | 채택 조건 |
| --- | --- |
| 호출 | 품질 비교 10건과 규모 시험 2건이 모두 채택 |
| 인용 | 주제·복습이 잡담 구간(s4, s28)을 인용하지 않음 |
| 규모 | 약 320개 목록의 입력이 예산(8,192 − 2,048 − 64 = 6,080토큰) 안 |
| 크기 검사 | 예산을 넘는 입력은 호출 없이 실패로 기록 |
| 품질 | 원응답을 읽어 주제·복습이 기존보다 나빠지지 않음(복습 항목 수, 주제가 강의 전체를 담는지) |

조건: AC 전원·"최고 성능", 전원 상태와 배경 부하를 기록한다. 시간 목표는 없다.

## 5. 한계

- 규모 시험의 목록은 합성 강의 개념을 되풀이한 것이다. 실제 긴 강의의 개념 분포와 다르다.
- 설명 없이 이름만 보면 이름이 모호한 개념("교착 상태 예시")의 복습 항목이 흐려질 수 있다. 실제 강의 평가셋(작업 9)에서 본다.

## 6. 재생 결과와 변경 (2026-09-28)

이름·출처만 넣은 재생에서 크기 기준은 통과했다. 10건과 규모 시험 2건이 모두 채택됐고, 개념 324개가 4,423토큰이었다. 그러나 품질 기준은 통과하지 못했다. 다룬 내용을 짚은 주제가 10건 중 9건에서 3건으로 줄었고, 복습 항목은 중앙값 8개에서 5개로 줄었다. 사용자 결정으로 입력을 예산에 맞춰 고른다.

- 설명을 넣은 입력(`- 이름 [출처]: 설명`)이 예산 안이면 그것을 쓴다(개념 약 100개, 약 90분 강의까지).
- 넘으면 이름·출처만 넣은 입력을 쓴다.
- 그것도 넘으면 호출하지 않고 `input_too_large`로 기록한다.
- 어느 형식을 썼는지 기록한다. 프롬프트 v2는 두 형식을 모두 "개념 목록"으로 설명한다.
