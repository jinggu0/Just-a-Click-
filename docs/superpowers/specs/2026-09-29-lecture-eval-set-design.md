# 강의 평가셋 설계

- 날짜: 2026-09-29
- 상태: 사용자 승인 설계. 형식·채점 도구·절차 구현 완료, 강의 1 초안 정답 기준 기준선 채점([보고서](../../validation/2026-09-29-lecture-eval-set.md)). 정답 검수와 강의 추가는 진행 중
- 대상: [로드맵](../../ROADMAP.md) M0 남은 작업 9(강의 평가셋의 형식과 합격 기준), [PRD](../../PRD.md) 8.2절 2, [LLM 지역화](../../LLM-SPECIALIZATION.md) 6절 내부 출시 기준
- 근거: [실제 강의 1차 검증](../../validation/2026-09-28-lecture-real-1.md). 강의 1개로 확인한 수정(잡음 조각, 공지, 코드)의 일반성을 확인할 수단이 없다

## 1. 사용자 결정

| 질문 | 결정 |
| --- | --- |
| 정답 작성 | Claude가 전사를 읽고 초안을 쓰고, 강의를 들은 사용자가 검수·확정한다 |
| 녹음 확보 | 이번 주 여러 과목 강의를 녹음한다. 각 강의자의 허락을 받는다 |

## 2. 데이터 위치와 권한

- 강의마다 `artifacts/eval-lectures/<강의 ID>/`를 둔다. 강의 ID는 `<과목 약칭>-<날짜>`(예: `sysprog-2026-09-28`)다.
  - `audio/`: 녹음 조각
  - `runs/<실행 이름>/`: `lecture_pipeline` 결과(`lecture-pipeline.json`, `transcript.txt`, 원응답)
  - `reference.json`: 정답
- 강의 음성·전사·정답은 강의자의 내용이므로 커밋하지 않는다(`artifacts/`는 이미 Git 제외).
- 커밋하는 것은 네 가지다: 정답 스키마, 채점 도구와 테스트, 문서, 강의 내용 없이 수치만 담은 집계(`evaluation/results/<날짜>-lecture-eval.json`).
- 정답에는 녹음 허락(허락한 사람, 사용 범위, 확인 날짜)을 적는다. 허락이 없으면 평가셋에 넣지 않는다.

## 3. 정답 형식 `lecture-reference-v1`

`schemas/lecture-reference-v1.json`으로 검증한다.

| 필드 | 내용 |
| --- | --- |
| `schema_version`, `lecture_id`, `course`, `date` | 식별 |
| `permission` | `granted_by`, `scope`, `confirmed_on` |
| `review` | `status`(`draft`·`reviewed`), `reviewer`, `notes` |
| `transcript_run` | 구간 ID의 기준이 된 실행 이름. 정답의 구간 ID는 이 실행의 `transcript.txt`를 따른다 |
| `facts[]` | `id`, `text`, `segments[]`, `importance`(`key`·`normal`) |
| `notices[]` | `kind`(`exam`·`assignment`·`announcement`), `content`, `date_text`, `scope_text`, `status`(`scheduled`·`cancelled`), `segments[]`. 공지가 없으면 빈 목록 |
| `code[]` | `code`(실제로 말하거나 보여 준 명령·코드, 올바른 표기), `segments[]` |
| `terms[]` | `heard`(전사된 표기), `correct`(올바른 표기), `segments[]` |

## 4. 채점 (`scripts/lecture_eval.py`)

처리 결과(`lecture-pipeline.json`)와 정답을 비교한다. 구간 ID는 같은 전사를 쓴 실행끼리만 비교할 수 있다. 전사가 다른 실행(다시 녹음·다른 STT)이면 채점하지 않고 알린다.

| 지표 | 계산 | 종류 |
| --- | --- | --- |
| 공지 재현율 | 정답 공지마다 같은 종류의 노트 공지가 근거 구간을 하나 이상 공유하면 찾은 것 | 자동 |
| 공지 정밀도·없는 공지 수 | 노트 공지 가운데 어떤 정답 공지와도 맞지 않는 것 | 자동 |
| 공지 상태·날짜 오류 | 맞은 공지 가운데 `status`가 다르거나, 날짜가 있는데 정답과 다른 것 | 자동 |
| 코드 재현율·정밀도 | 공백·대소문자를 무시한 문자열 일치 | 자동 |
| 용어 표기 | 정답 용어마다 올바른 표기가 전사·노트에 나오는 비율 | 자동 |
| 핵심 사실 재현율(대리) | 핵심 사실마다 노트의 개념·예제·용어·요점 가운데 근거 구간을 공유하는 항목이 있으면 찾은 것. 5분 노트와 정밀 정리를 따로 계산 | 대리 지표. 최종 판정은 사람 검수 |
| 시간 | `after_recording_seconds`, 녹음 중 창 초안 시간. AC 여부와 함께 기록 | 자동 |

근거 충실성(98%)과 사용성 점수는 사람이 판정한다. 도구는 사실 단위 확인표만 만든다(이번 범위에서는 표 형식만 정의).

## 5. 합격 기준 v1

| 지표 | 기준 |
| --- | --- |
| 핵심 사실 재현율 | 95% 이상(대리 지표로 먼저 보고, 사람 검수로 확정) |
| 없는 공지 | 0건 |
| 공지 날짜 오류 | 0건 |
| 정답 공지 재현율 | 100%, 상태 오류 0건 |
| 5분 노트 시간 | AC·"최고 성능"에서 녹음 종료 후 300초 이하 |
| 코드·용어 | 기준선만 기록한다. 목표는 강의 5개를 모은 뒤 정한다 |

기준은 강의별로 판정하고 전체 집계도 낸다. 평가셋에서 0건이라는 결과를 모든 입력의 보장으로 표현하지 않는다.

## 6. 진행 순서

1. 녹음 절차 체크리스트(`evaluation/README.md` 강의 평가셋 절): 허락 확인, AC 연결·뚜껑 열기, 과목명, 시작·종료 명령, 녹음 뒤 정답 초안 요청.
2. 강의 1(`sysprog-2026-09-28`): 기존 녹음 조각으로 현재 코드를 재생 처리한다. 그 전사로 정답 초안을 쓰고 사용자에게 검수를 요청한다.
3. 검수된 정답으로 기준선을 채점한다. 검수 전 결과는 "초안 정답 기준"으로 표시한다.
4. 이번 주 강의를 녹음되는 대로 추가해 5개를 채운다.

## 7. 한계

- 초안 정답은 모델 결과를 본 Claude가 쓰므로 결과 쪽으로 치우칠 수 있다. 검수자는 빠진 사실을 더하는 데 집중한다.
- 구간 겹침 기반 사실 재현율은 대리 지표다. 같은 구간을 인용하고 틀린 내용을 쓴 경우를 잡지 못한다.
- 한 사람이 녹음·검수하므로 평가자 간 일치도는 없다.
