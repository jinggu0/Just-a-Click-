## 요약

- 스키마 제약 없는 Vulkan 생성 속도는 지속 상태에서 깊이 0 기준 약 3.8~4.0 tok/s였다. 스레드 수(4·8)와 Flash Attention on/off의 차이는 약 4% 이내였다.
- 같은 프롬프트에서 서버 출력 제약만 바꾼 결과, 생성 속도는 none 3.44, json 3.75, schema 3.72 tok/s였다. 문법 제약에 의한 속도 저하는 관측되지 않았다.
- 측정 중 SoC 전력은 중앙값 약 6.9W로 낮았다. AC 연결 상태의 Windows 전원 모드는 "최고의 전원 효율성"이었다. 한 작업에서만 일시적으로 생성 13.9 tok/s가 관측돼 기기의 순간 성능은 더 높을 수 있다(원인 미검증).
- 지속 성능 기준 1차 판정(추정)은 **infeasible_estimate**다. 녹음 중 처리(점유율 0.33~0.35)는 가능하지만 녹음 종료 후 시간이 350~364초로 5분 목표를 약 17~21% 넘었다. 다시 요약은 2시간 강의만 목표 안에 들었다.

## 출력 제약 비교

같은 엄격한 프롬프트(입력 926토큰)에서 서버의 출력 제약만 바꿨다. 스레드 8, Flash Attention on, 각 3회다.

- 문법 제약 영향(schema ÷ none) = 1.083. 스키마 제약에 의한 감속은 관측되지 않았다. none이 가장 먼저 실행돼 상태 차이가 섞였을 수 있으므로 약 8% 차이는 변동 범위로 본다.
- 서버·샘플링 영향: 같은 깊이(생성 구간 평균 약 1,090토큰)의 llama-bench 지속 생성 추정값 3.794 tok/s 대비 none은 0.906, schema는 0.981이었다. 추정기는 schema 값을 생성 보정 계수 0.981로 사용했다.
- 오전 계약 시험의 schema 생성 속도(2.58·2.92 tok/s)가 이번보다 낮았던 이유는 문법 제약이 아닌 실행 환경 차이일 가능성이 크다. 당시에는 전원 상태를 기록하지 않아 확인하지 못했다.
- none 모드도 이번 합성 사례에서는 계약을 통과했다. 이는 제약 없는 생성이 항상 유효한 JSON을 낸다는 근거가 아니다.

- 다시 요약: 2시간 강의는 2,529~2,688초로 목표 안이다. 3시간 강의는 3,718~3,956초로 약 3~10% 넘었고, 4시간은 4,906~5,223초다.
- 참고: 계획대로 전체 기록으로 계산하면 고속 구간이 섞여 입력 처리 곡선(ubatch 512, 깊이 0에서 651.5 tok/s)과 생성 곡선(8.67·4.35·2.91 tok/s)이 왜곡된다. 그 결과 보정 계수가 0.585로 낮아지고 판정은 역시 infeasible_estimate였다. 이 값은 판정에 쓰지 않는다.

## 판정과 다음 결정

현재 기기·전원 모드("최고의 전원 효율성")의 지속 성능 기준 1차 판정은 **infeasible_estimate**다. 차이는 근소하다. 녹음 종료 후 5분 목표는 약 17~21%, 3시간 다시 요약은 약 3~10% 부족하다. 이 판정은 원시 처리량과 가정으로 계산한 추정이며 앱 지연시간이나 출시 품질의 판정이 아니다.

결정 0006에 따라 모델·목표를 임의로 바꾸지 않고 다음 선택지를 사용자에게 제시한다.

1. 사용자가 전원 모드를 "최고 성능"으로 바꾼 뒤 같은 측정을 반복한다. 저전력 상태의 증거(SoC 약 6.9W, GPU 연산 79% 사용, 일시적 13.9 tok/s)가 있고, 필요한 개선 폭이 약 20~30%이기 때문이다. 수업 중 배터리 사용 조건과는 따로 판정해야 한다.
2. 구간 출력량(300토큰)·최종 출력량(400토큰)이나 구간 길이를 조정한다. 품질 평가가 함께 필요하다.
3. 녹음 종료 후 목표 시간을 조정한다.
4. SYCL 등 다른 가속 경로를 비교하거나 모델 재검토를 별도 결정으로 진행한다.

앱 설계에도 영향이 있다. 전원 모드와 백그라운드 전력 제한이 추론 속도를 크게 바꿀 수 있으므로, 앱이 실행 시 전원 상태를 기록하고 처리 시간 목표를 판정할 때 함께 표시해야 한다. 추론 프로세스의 전력 제한 해제 같은 프로세스 단위 조치는 별도 검증 대상이다.

## 한계

- 합성 토큰(llama-bench)과 합성 회의 프롬프트 1건만 사용했고, 실제 강의 전사문과 STT는 포함하지 않았다.
