# M0 첫 로컬 LLM 실행 검증

- 작업일: 2026-09-17
- 범위: Qwen3-8B Q5_K_M의 짧은 합성 회의문 요약. 실제 음성·4시간 요약 시험이 아님
- 재현 방법: [평가 실행 안내](../../evaluation/README.md)

## 준비 결과

- 공식 모델 파일 5,851,112,224 bytes를 다운로드하고 manifest의 SHA-256과 일치함을 확인했다.
- 공식 llama.cpp b10994 CPU·Vulkan zip도 각각 SHA-256을 확인했다. 실행 버전은 `0.4.1-dev`, build 10994, commit `0a8b29a60`이다.
- 모델 라이선스 파일을 로컬에 저장했다. 모델·런타임·원본 실행 로그는 Git에서 제외한다.
- 다운로드 중 한 구간의 불완전 수신이 발생했다. 완성된 구간을 보존한 채 재실행하여 해당 구간을 다시 받고 전체 해시 검증에 성공했다.
- Vulkan 장치 목록에서 Intel Arc 140V가 인식됐다. 장치 인식과 실제 GPU 추론 성공은 구분한다.

## 측정 조건

기준 PC는 Samsung 940XHA / Core Ultra 7 258V / RAM 약 31.5 GiB / Windows 11이다. 준비 단계에서 전원 연결·충전 상태와 Samsung 전원 모드를 확인했다. 다른 프로그램 부하·온도·실시간 전력은 통제하지 않았으므로 시간 편차의 원인을 단정하지 않는다.

- 입력: 직접 작성한 `meeting-smoke-v1`, 프롬프트 446토큰(CPU 관측).
- 컨텍스트 16,384, 8스레드, 1슬롯, seed 42.
- non-thinking, temperature 0.7, top_p 0.8, top_k 20, min_p 0.
- JSON object 형식, 출력 상한 1,536토큰. 제한 도달 시 완료로 판단하지 않는다.
- 요청별 프롬프트 캐시 비활성화. 모델 프로세스는 backend별 1회 시작한다.
- 준비 시간은 프로세스 시작부터 health 응답까지, 요청 시간은 HTTP 요청부터 응답 파일 저장까지다. 제품 전체 저장·렌더링 경로는 아직 없다.
- 모델 파일은 사전 해시 검사로 OS 파일 캐시에 들어갔을 수 있다. 첫 프로세스 실행을 디스크 캐시가 없는 cold start로 부르지 않는다.

두 경로 모두 3회 정상 종료했고 JSON 필수 최상위 필드가 존재했다. `finish_reason=stop`이며 사고 과정 출력은 관측되지 않았다. CPU 출력은 매회 281토큰, GPU 출력은 매회 292토큰으로 달랐다. 경로별 3회 내용은 동일했지만 CPU와 GPU 사이의 내용은 달랐으므로 순수한 동일 토큰 생성 벤치마크로 해석하지 않는다.

- CPU 입력 처리 4.13~10.56토큰/초, 생성 2.13~2.34토큰/초.
- Vulkan 입력 처리 86.52~143.46토큰/초, 생성 3.51~3.77토큰/초.
- 관측한 요청 중앙값은 Vulkan이 CPU보다 약 2.42배 빨랐다. 다른 기기·길이·입력의 성능 보장은 아니다.
- 준비를 포함한 첫 실행은 두 경로 모두 120초를 초과했다. Vulkan의 준비 후 짧은 요청만 120초 이하였다.
- **제품의 4시간 입력·120초 목표와 출시 품질은 미통과 상태로 유지한다.** 이 시험은 최대 메모리, STT, 실제 4시간 입력, 전체 앱 저장 경로 및 네트워크 차단 동작을 검증하지 않았다.

원시 측정값과 검수한 출력: [CPU 결과](../../evaluation/results/2026-09-17-cpu-smoke.json), [Vulkan 결과](../../evaluation/results/2026-09-17-vulkan-smoke.json). 공개 가능한 합성 입력의 결과만 커밋하며 인증 토큰·전체 서버 로그는 포함하지 않는다.

## 초기 출력 검수

CPU 3회 응답은 같은 내용이었다. 서버 업로드 취소·로컬 보존, 지민의 재시도 기능 담당, SHA-256 실패 처리, 전사 시간이 2분에서 제외된다는 사실, GPU 미측정 상태를 보존했다. 잡담은 제외했고 출력한 항목의 출처 ID는 해당 원문과 연결되었다.

다만 **마감일을 정하지 않았다는 정보가 누락되고 `deadline: null`이 표현되지 않았다.** 필수 최상위 필드가 있는 JSON이라는 검사만으로 도메인 규약을 지켰다고 판단할 수 없다. 후속 작업에서 action 필드의 명시적 스키마와 미정 값 검사를 추가해야 한다.

Vulkan은 지민의 작업에 `owner`와 `deadline: null`을 모두 보존했다. 그러나 GPU 미측정 상태를 후속 작업 배열에 넣고 그 항목에는 owner·deadline을 제공하지 않았다. 핵심 사실의 창작은 관측되지 않았지만 항목 분류와 구조 일관성은 개선해야 한다. 이는 1개 합성 사례의 수동 검수 결과이며 일반적인 품질 보장은 아니다.

실제 강의·회의 평가셋이 없으므로 이 결과에 사실 재현율 95%·근거 충실성 98% 등 출시 품질 합격을 부여하지 않는다. 모델 학습·파인튜닝도 수행하지 않았다.

## 후속 검증

1. 담당자·기한·상태·출처를 명시하는 결과 스키마와 의미 검사를 구현한다.
2. CPU·Vulkan 결과를 바탕으로 가속 설정을 정하고 실제 전사문 길이를 늘려 입력 처리 병목을 측정한다.
3. 실제 권한 있는 한국어 음성의 STT와 전사·요약 연결을 검증한다.
4. 4시간 입력과 품질 기준·120초 목표는 별도 통과가 필요하다. 짧은 입력 성공으로 대체하지 않는다.

현재 런타임은 `enable_thinking` 템플릿 인자의 deprecated 경고를 낸다. 이번 측정은 해당 설정으로 수행했으며, 후속 런타임 정리 시 `--reasoning off`로 옮기고 동일한 비사고 출력인지 확인한다. 기존 측정의 실행 설정을 소급 변경하지 않는다.
