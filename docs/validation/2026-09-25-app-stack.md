# 앱 기술 검증 1차: Tauri 2 빌드와 녹음

- 날짜: 2026-09-25
- 범위: [결정 0007](../decisions/0007-app-stack.md) 3절 ①②. Tauri 2 빌드와 WebView2 동작, 마이크·시스템 소리(WASAPI 루프백) 녹음, 일시정지·재개, 30초 구간 파일 저장, 절전 방지를 확인했다. ③④⑤(추론 프로세스 관리, SQLite 한국어 검색, 자격 증명 저장)는 2차 검증에서 다룬다
- 기기: 기준 노트북(Intel Core Ultra 7 258V, 8코어·8논리, Intel Arc 140V, RAM 약 31.5GiB), [0001](../decisions/0001-target-environment.md). Windows 11 Home 10.0.26200
- 조건: AC 전원·Windows 전원 모드 "최고 성능", 배터리 83%, 경쟁 프로세스 없음
- 결과 파일: 녹음은 사용자 음성이므로 `artifacts/app-recordings/`에만 두고 커밋하지 않는다. 코드는 [`app/`](../../app)에 있다
- 설계·계획: [검증 설계](../superpowers/specs/2026-09-23-app-stack-validation-design.md), [실행 계획](../superpowers/plans/2026-09-25-app-stack-validation.md)

## 1. 요약

**결정 0007의 ①②가 통과했다.** Rust 1.98.1·Tauri 2.11.6·WebView2 153으로 개발 실행과 릴리스 빌드(설치 파일 2종)가 모두 성공했고, 릴리스 실행 파일이 한국어 제목의 창을 띄웠다. 마이크와 시스템 소리를 16kHz 모노 PCM16 30초 조각으로 녹음해 whisper-cli 전사까지 확인했고, 일시정지 10초는 녹음 길이에서 정확히 빠졌다.

30분 연속 녹음에서는 조각 60개(마지막 29.59초만 짧음)에 1,799.59초를 담아 경과 시간과 어긋나지 않았고, 녹음 프로세스의 전용 메모리는 1.7~1.8MiB로 늘지 않았다. 6분 무렵 오디오 장치가 0.25초 멈춰 불연속이 14회 보고됐지만 앱이 그만큼 무음을 채워 시간축을 유지했다.

루프백에는 제약이 셋 있었다(6절). 재생 장치를 캡처 방향으로 초기화해야 하고, 16kHz 모노 자동 변환은 거부되므로 앱이 직접 변환해야 하며, 재생이 없는 구간에는 이벤트가 오지 않아 앱이 무음을 채워 시간축을 맞춰야 한다. 그리고 무음 조각을 그대로 전사하면 없던 말이 생기므로 전사 전에 무음 조각을 걸러야 한다.

| 오디오 | `wasapi` 0.24.0(MIT), 그 의존성 `windows` 0.62.2(MIT OR Apache-2.0) |

리샘플링에는 `rubato` 5를 먼저 검토했으나 별도 버퍼 어댑터 크레이트를 요구해 쓰지 않고, 창 함수를 적용한 sinc 보간(반폭 32탭, Blackman 창)을 직접 구현했다. 통과 대역과 차단 대역은 단위 테스트로 확인한다(1kHz 진폭 유지, 12kHz 5% 미만).

## 3. 빌드와 실행

- 단위 테스트 22개가 통과하고, 실제 오디오 장치를 쓰는 테스트 3개도 `cargo test -- --ignored`로 통과했다. TypeScript 타입 검사도 통과했다.
- `npm run tauri dev`가 Vite 화면과 Rust 코어를 빌드해 앱 창을 띄웠다.
- 릴리스 빌드(`npm run tauri build`)는 `Finished 'release' profile in 5m 42s`로 끝났고 번들 2개를 만들었다.

| 산출물 | 크기 |
| --- | --- |
| `app/src-tauri/target/release/app.exe` | 4.10MiB |
| `…/bundle/msi/Just a Click_0.1.0_x64_en-US.msi` | 2.00MiB |
| `…/bundle/nsis/Just a Click_0.1.0_x64-setup.exe` | 1.36MiB |

- 번들 단계에서 Tauri가 WiX 3.14.1과 NSIS 3.11을 내려받아 해시를 확인했다. 개발 기기에서 한 번 받는 빌드 도구이며 앱 실행에는 필요 없다.
- 릴리스 실행 파일을 실행하니 "딸깍! 녹음 검증" 제목의 창이 뜨고 WebView2 렌더러 6개가 함께 떴다. 이 프로세스 묶음의 전용 메모리는 197.4MiB(작업 집합 410.8MiB)이고 그중 실행 파일 자신은 4.8MiB다. [동시 실행 측정](2026-09-23-concurrency.md)의 16GB 예산 여유 1,060MiB에서 앱 몫을 빼면 약 863MiB가 남는다.
- 화면은 Vite가 띄운 페이지를 브라우저로 열어 한국어 레이블·버튼·상태 표시가 그려지는 것과, Tauri 호출이 없는 환경에서 "장치 조회 실패"를 기록에 남기고 멈추지 않는 것을 확인했다.
- 녹음 자체는 화면과 같은 `Recorder` API를 호출하는 [`record_check` 예제](../../app/src-tauri/examples/record_check.rs)로 실행했다. 시간을 정확히 맞추고 같은 절차를 반복할 수 있기 때문이다. **WebView2 창 안에서 버튼을 눌러 녹음하는 경로는 이번에 확인하지 않았다.**
- 빌드 경고가 하나 있다. 번들 식별자 `dev.justaclick.app`가 `.app`로 끝나 macOS 번들 확장자와 겹친다는 경고다. Windows 전용이라 동작에는 영향이 없고, 앱 데이터 경로를 정할 때([로드맵](../ROADMAP.md) 남은 작업 10) 함께 정리한다.

## 4. 녹음

모든 조각은 16kHz·모노·16비트 PCM WAV이고, 마지막 조각을 빼면 정확히 30.00초다.

| 확인 | 조각 | 합계 길이 | 결과 |
| --- | --- | --- | --- |
| 마이크 60초 | 30.00 + 30.00 + 4.38초 | 64.38초 | 사용자 말소리가 한국어로 전사됐다 |
| 시스템 소리 60초 | 30.00 + 30.00 + 4.71초 | 64.71초 | 재생한 영상의 말소리가 한국어로 전사됐다. 재생 전 조각은 무음(최대 진폭 0)이다 |
| 일시정지·재개 | 30.00 + 30.00 + 24.93초 | 84.93초 | 경과 95초에서 일시정지 10초를 뺀 값과 같다. 일시정지 구간의 소리는 조각에 없다 |
| 30분 연속 | 30.00초 59개 + 29.59초 | 1,799.59초 | 경과 1,800초와 어긋나지 않았다. 조각 60개 모두 형식이 같다 |

- 시스템 소리 60초에서는 재생이 시작되기 전 47.9초를 앱이 무음으로 채웠다. 불연속 12회는 무음과 소리가 바뀌는 지점에서 보고됐다.
- 30분 연속의 불연속은 15회다. 1회는 스트림 시작 표시이고, 2회는 5분 50초 지점, 12회는 6분 20초 지점에 몰렸다. 같은 구간에서 앱이 0.25초를 무음으로 채웠고 그 뒤 24분 동안은 한 번도 늘지 않았다. 녹음 길이는 계속 경과 시간과 같았다(6분 20초 시점 379.5초 / 380초).
- 녹음 프로세스의 메모리는 세 번(약 5분·11분·21분) 재서 전용 1.8/1.8/1.7MiB, 작업 집합 11.4/11.5/11.5MiB였다. 30초마다 조각을 파일로 닫으므로 오디오가 메모리에 쌓이지 않는다.
- 조각이 30초마다 닫히므로 중간에 실패해도 그 시점까지의 녹음이 파일로 남는다.

## 5. 절전 방지

- 녹음 중에는 `SetThreadExecutionState(ES_CONTINUOUS|ES_SYSTEM_REQUIRED|ES_DISPLAY_REQUIRED)`로 절전과 화면 꺼짐을 막고, 녹음이 끝나면 `ES_CONTINUOUS`로 되돌린다. 시스템 전원 설정은 바꾸지 않는다.
- Windows가 요청을 받았는지는 반환값으로 확인한다. 이 함수는 성공하면 이전 상태를, 거부하면 0을 돌려준다. [`power.rs`](../../app/src-tauri/src/power.rs)의 테스트가 실제 호출의 반환값이 0이 아님을 검사하고, 해제도 `Drop`에서 같은 경로로 호출한다.
- **시스템 수준 확인은 미검증이다.** `powercfg /requests`는 관리자 권한이 필요해 이번에 실행하지 못했다. 또 이 기기의 전원 계획은 AC·배터리 모두 절전 전환과 화면 끄기가 "안 함"이므로, 30분 녹음이 끊기지 않은 것만으로는 차단 효과를 판정할 수 없다.
- 참고로 같은 API를 쓰기 전 STT 측정에서는 Modern Standby가 2시간 작업을 네 번 끊었고, `ES_DISPLAY_REQUIRED`를 더한 뒤로는 끊기지 않았다([STT 보고서](2026-09-18-stt-bench.md) 2절).

## 6. 발견한 제약

1. **루프백은 재생 장치를 캡처 방향으로 초기화해야 한다.** 기본 재생 장치를 열고 `initialize_client`에 `Direction::Render`를 주면 실패한다. `Direction::Capture`를 줘야 WASAPI가 루프백으로 잡는다.
2. **루프백은 믹스 형식만 받는다.** 16kHz 모노를 요청하거나 자동 변환(`autoconvert: true`)을 켜면 `AUDCLNT_E_UNSUPPORTED_FORMAT`(0x88890003)이 난다. 그래서 장치 믹스 형식(이 기기는 48kHz·2채널·f32)으로 받아 앱에서 16kHz 모노 PCM16으로 변환한다.
3. **재생이 없으면 이벤트가 오지 않는다.** 대기 시간 초과를 실패로 다루면 녹음이 멈추고, 그대로 두면 시간축이 밀린다. 그래서 초과는 정상으로 보고, 경과 시간보다 0.25초 이상 뒤처진 만큼 무음을 채운다.
4. **깨어날 때마다 큐에 쌓인 패킷을 모두 읽어야 한다.** `read_from_device_to_deque`는 한 번에 패킷 하나만 주므로 이벤트마다 한 번만 읽으면 뒤처져 드라이버가 불연속을 보고했다(14초에 3회). `get_next_packet_size`로 큐가 빌 때까지 반복하자 20초에 1회(스트림 시작 표시)로 줄었다.
5. **무음 조각을 그대로 전사하면 없던 말이 생긴다.** 시스템 소리 확인에서 최대 진폭 0인 조각이 "감사합니다."로 전사됐다. 전사 전에 무음 조각을 걸러야 한다.

## 7. 판정과 다음 결정

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| ① Rust·MSVC·Tauri 2 빌드 | 통과 | 개발 실행과 릴리스 빌드 성공(3절) |
| ① WebView2 동작 | 조건부 통과 | 릴리스 앱이 창을 띄우고 WebView2 렌더러 6개가 떴다. 화면도 브라우저에서 렌더링을 확인했다. Windows 10과 창 안에서의 조작은 미검증(3절) |
| ② 마이크·시스템 소리 녹음 | 통과 | 두 원본 모두 16kHz 모노 PCM16 조각과 전사 확인(4절) |
| ② 일시정지, 구간 파일 저장 | 통과 | 일시정지 10초가 정확히 빠지고 30초마다 파일이 닫힌다(4절) |
| ② 장시간 녹음 | 통과(30분) | 조각 60개·1,799.59초, 메모리 증가 없음. 4시간은 미검증(4절) |
| ② 절전 방지 | 조건부 통과 | API 호출이 수락됐다. 시스템 수준 확인은 관리자 권한이 필요해 미검증(5절) |

앱 프로세스 묶음의 전용 메모리 197.4MiB는 16GB 예산 여유(1,060MiB) 안에 들지만 그 5분의 1을 쓴다. 16GB 실기기 확인 때 함께 본다.

결정 0007을 유지한다. 2차 검증에서 ③ 추론 프로세스 관리, ④ SQLite FTS5 한국어 검색, ⑤ Windows 자격 증명 관리자를 확인한다. 제품 구현에는 제약 5(무음 조각 제외)를 STT 단계 앞에 넣고, 불연속·무음 보정 값을 녹음 상태에 남겨 사용자에게 알린다.

## 8. 한계

- 기기 1대·Windows 11 Home 10.0.26200에서만 확인했다. Windows 10과 RAM 16GB 기기는 미검증이다.
- 화면 버튼으로 녹음하는 경로, 녹음 중 장치 분리·전환, 4시간 연속 녹음, 실제 강의 환경은 시험하지 않았다.
- 전사는 원본이 한국어로 들어오는지 보는 확인이며 품질 판정이 아니다. 품질은 [STT 보고서](2026-09-18-stt-bench.md)를 따른다.
- 절전 방지의 시스템 수준 확인과 절전 설정이 켜진 기기에서의 동작은 미검증이다.
