## 1. 요약

**창 기준은 통과, 녹음 종료 후 기준은 5회 중 1회 미달(320초)이다.** 생성 속도는 초당 10.5토큰(중앙값)으로 50분 내내 8.7~11.1 사이에서 유지됐고 v1 측정처럼 중간에 떨어지지 않았다. 패키지 전력은 처음부터 끝까지 약 20W에 붙어 있었고 열 제한 카운터는 100%(제한 없음)였다. 생성 속도는 GPU 전력과 같이 움직이고(상관 +0.82) 코어 전력과 반대로 움직인다(−0.62). 즉 약 20W 패키지 예산을 CPU 코어와 GPU가 나눠 쓰며, 코어 쪽 부하가 늘면 생성이 느려진다. 이번 측정에는 배경 CPU 부하가 컸으므로, 이 부하를 없애고 한 번 더 재야 녹음 종료 후 판정을 닫을 수 있다.

생성 속도와의 상관: GPU 전력 +0.82, 프로세서 성능 +0.69, 코어 전력 −0.62, 온도 −0.21, 패키지 전력 +0.07. 수동 제한과 충전량은 변하지 않아 상관을 구할 수 없었다.

- **패키지 전력 한도.** 측정 전체에서 패키지 전력 중앙값이 20.0W(최소 16.4, 최대 24.6)로 거의 일정했다. 속도가 바뀌어도 합계는 그대로이고 GPU와 코어의 몫만 바뀐다. 한도가 어디서 오는지(펌웨어 전력 한도 등)는 확인하지 않았다.
- **발열.** 온도는 83~93℃(열 영역 기준)였지만 수동 제한은 한 번도 걸리지 않았고, 속도와의 상관도 약했다.
- **충전.** 이번에는 충전이 없었고 속도가 떨어지지 않았다. 충전 중이던 v1·v2 측정은 6.7~7.4토큰/초였다. 충전이 예산을 줄인다는 설명과 맞지만 충전 중 카운터는 기록하지 않았으므로 확인되지 않았다.
- **배경 부하.** 코어 전력이 늘면 속도가 떨어지므로 OneDrive·검색 색인 같은 배경 CPU 작업이 GPU 몫을 빼앗는 것으로 보인다. 측정 직전 시험(12.9토큰/초)과 이번(10.5) 차이도 배경 부하 차이일 수 있으나, 시험 때 부하는 기록하지 않았다.

## 4. 품질 재확인

호출 75건과 노트 10건이 재시도 없이 모두 채택됐다. 판정용 기대치는 1건이 깨졌다: 1회 정밀 정리(전체 전사)의 `topic`이 구간 36개를 모두 인용해 잡담 구간(s4, s28)이 들어갔다(`chatter_excluded` 24/25). 주제 문장 자체는 정상이고, 전체를 요약하는 항목이 모든 구간을 인용할 때 기대치가 이를 잡담 반영으로 센다. v2 측정의 5/5 통과와 달리 이번에는 통과하지 못했으므로 계약 채택은 유지하되 다음 작업에서 다룬다(예: `topic`의 인용 수 제한).

## 5. 판정

| 항목 | 판정 |
| --- | --- |
| 창 하나 ≤ 150초 | **통과.** 15/15, 최대 93.7초 |
| 녹음 종료 후 ≤ 300초 | **미달.** 4/5, 최대 320.0초. 배경 CPU 부하가 큰 상태의 측정이다 |
| 속도 저하 원인 | 약 20W 패키지 전력 예산을 GPU와 CPU 코어가 나눠 쓰는 구조가 확인됐다. 충전과 배경 부하가 GPU 몫을 줄이는 것으로 보이나 둘 다 직접 확인하지는 않았다 |

다음 측정은 OneDrive 동기화 일시 중지·가상 머신 종료 등 배경 부하를 사용자가 줄인 상태에서 같은 방법으로 한다. 넘친 폭이 20초이므로, 부하를 줄여도 넘으면 5분 노트 본문 출력(1,000토큰 안팎)을 줄이는 쪽을 검토한다.

→ [시간 재측정 2](2026-09-27-lecture-contract-timing-2.md): OneDrive를 멈추고 다시 재서 창 15/15, 녹음 종료 후 5/5(최대 249초)로 통과했다. 그 측정에서 패키지 전력은 23W였으므로 위의 "약 20W 예산"은 고정 한도가 아니었다.
