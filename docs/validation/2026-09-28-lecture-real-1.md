## 1. 요약

**흐름은 끝까지 동작했고 시간도 기준 안이었지만, 노트 품질은 실제 강의에서 새 문제를 드러냈다.** 30분 녹음(61조각)을 녹음 중에 모두 전사했다(실시간의 0.46배). 창 초안은 창마다 66~109초에 끝났다. 호출 30건이 재시도 없이 모두 채택됐다. 5분 노트는 녹음 종료 252초 뒤에 저장됐고(목표 300초), 정밀 정리는 그 뒤 416초가 걸렸다. 다만 녹음 종료 뒤 처리는 배터리에서 이뤄졌으므로 시간 판정 조건(AC)에서 벗어난 참고값이다.

5분 노트의 개념 8개는 강의의 큰 흐름(생성·퍼미션·디스크립터·read/write·lseek)을 담았다. 그러나 다음 문제가 있었다.
1. 없는 공지 3건이 생겼다.
2. 코드 목록이 개념 단어로 가득 찼다.
3. 마지막 0.43초 조각의 전사 잡음("소고가")에서 정밀 정리가 없는 개념과 정의를 지어냈다.
4. 정밀 정리의 복습이 앞쪽 개념 이름 10개를 되풀이했다.
5. API 이름의 전사 오류가 노트에 그대로 들어갔다.

## 3. 노트 품질 (원문 대조)

| 항목 | 관찰 |
| --- | --- |
| 5분 노트 개념 | 8개. 파일 생성·쓰기·종료·퍼미션·디스크립터, read/write 반환값, lseek. 블루투스 누적 읽기와 파일 복사는 예제로 들어갔다. 파일 오프셋 자동 이동과 프레임버퍼 예시는 빠졌다 |
| 정밀 정리 개념 | 40개. exclusive 플래그, 디스크립터 재할당, read 반환값(음수·0·양수), 분할 수신 누적, 파일 오프셋 자동 이동, whence 세 가지까지 자세히 담았다. 대신 "read 함수 동작", "데이터 크기 확인", "read 함수의 동작 원리"처럼 이름만 다른 비슷한 개념이 많다 |
| **지어낸 개념** | 마지막 0.43초 조각이 "소고가"로 전사됐다. 정밀 정리 창 7은 이를 "스케줄링으로 자원 효율을 높이는 기법"이라는 개념·용어로 지어냈고, 주제도 "파일 처리 및 시스템 자원 관리 기법"으로 끌려갔다. 인용 구간은 실제로 존재하므로 출처 검사를 통과했다. 5분 노트에는 들어가지 않았다 |
| **없는 공지** | 공지 3건이 모두 강의 내용이었다. 파일 복사 예제의 문자열이 "시험", 블루투스 수신 설명이 "과제", 누적 읽기 설명이 "시험"으로 분류됐다. 실제 강의에서는 시험·과제 공지가 없었다 |
| **코드 목록** | 31개 가운데 `seek_set`·`seek_current`·`seek_end` 정도만 코드답다. 나머지는 "fd", "buffer", "Bluetooth", "while loop", "long" 같은 개념 단어나 "l식 함수", "lc 함수"(lseek 오인식)였다. 블루투스 설명에서 나온 6개는 s31~s40 전체를 인용했다. 실제 코드 줄(`open(...)`의 인자 등)은 강의에서 말로만 설명돼 목록에 없다 |
| 정밀 정리 복습 | 10개 모두 앞쪽 개념 이름("파일 생성 방법", "파일 디스크립터 반환" …)을 그대로 옮겼고, s1~s15만 다룬다. 뒤쪽(read 반복·오프셋·lseek)은 빠졌다 |
| 5분 노트 복습 | 3개(퍼미션, read/write 반환값, lseek)로 적지만 적절하다 |

## 5. 다음 작업 제안 (우선순위)

1. **짧은·잡음 조각 제외:** 몇 초 미만의 마지막 조각은 전사하지 않고, 조각 1~2개뿐인 마지막 창은 앞 창에 붙인다. 결정적이고 지어낸 개념의 직접 원인이다.
2. **공지 정밀도:** 예제 설명·코드 동작 설명을 공지로 분류하지 않게 한다. 공지가 날짜·범위·제출 같은 운영 신호 없이 설명 문장만 인용하면 거르는 결정적 검사를 검토하고, 실제 강의 평가셋으로 확인한다.
3. **코드 정밀도:** 코드 항목은 명령어·함수 호출 형태이거나 원문에 영문 그대로 있어야 한다는 규칙을 더하고, 넓은 구간 인용(구간 10개)을 제한한다.
4. **정밀 정리 복습:** 개념이 많을 때 앞쪽만 복습하는 문제를 합성 프롬프트나 창별 복습 후보로 다룬다.
5. **전사 용어 교정:** 강의 자료·과목 용어집 기반 교정(로드맵의 자료 연동·검색 교정)과 연결한다.
