## 1. 요약

**합성 입력은 예산에 맞춰 고른다.** 설명을 넣은 목록이 예산 안이면 그것을 쓰고, 넘으면 이름·출처만 쓰고, 그것도 넘으면 호출하지 않는다. 예산은 컨텍스트 8,192 − 최대 출력 2,048 − 템플릿 몫 64 = 6,080토큰이다.

처음 설계한 이름·출처만 넣는 방식은 크기를 해결했다. 개념 324개가 4,423토큰이었다. 그러나 주제·복습이 흐려져 품질 기준을 통과하지 못했다. 예산 선택 방식은 합성 강의 크기에서 설명 형식을 골라 기존 품질을 유지했다. 긴 강의 크기에서는 이름 형식을 골라 채택됐다.

설명 형식은 개념 한 줄이 약 53토큰이므로 개념 약 108개(약 90분 강의)까지 들어간다. 이름 형식은 한 줄이 약 13토큰이라 개념 약 450개까지 들어간다(추정).

## 3. 품질: 주제와 복습

같은 병합 결과 10건에 대한 세 가지 합성이다. "기존"은 측정 때 설명 형식으로 쓴 것이다.

| 항목 | 기존(설명) | 이름·출처만 | 예산 선택(설명) |
| --- | --- | --- | --- |
| 다룬 부분을 짚은 주제(예방·회피·탐지·회복 등 셋 이상) | 9/10 | **3/10** | 9/10 |
| 복습 항목 수 중앙값(범위) | 8(5~10) | **5(3~7)** | 7(5~10) |
| 첫 시도 채택 | — | 10/10 | 10/10 |
| 잡담 구간 인용 | 0 | 0 | 0 |

이름·출처만 넣었을 때 주제는 "교착 상태의 개념과 해결 전략에 대한 이해"처럼 흐렸다. 복습에는 "탐지 방법과 타조 알고리즘의 차이", "세마포어와 타조 알고리즘"처럼 관계없는 개념을 짝지은 항목이 생겼다. 설명 형식으로 다시 돌리자 주제가 "교착 상태의 원인, 예방, 회피, 탐지 방법 및 관련 알고리즘"처럼 기존과 비슷해졌다. 규모 시험(이름 형식)의 복습은 10개 모두 개념 하나나 둘을 짝지은 무난한 항목이었다.

## 4. 판정

| 기준(설계 4·6절) | 결과 |
| --- | --- |
| 재생 10건과 규모 시험 2건 채택 | **통과** 12/12(모두 첫 시도) |

| 품질이 기존보다 나빠지지 않음 | 이름·출처만: **미달**. 예산 선택: 합성 강의 크기에서 **통과** |

## 5. 한계

- 규모 시험의 목록은 합성 강의의 개념을 되풀이한 것이다. 긴 강의에서 이름 형식으로 쓴 주제·복습의 품질은 실제 강의(작업 4)에서 확인해야 한다.
- 품질 판정은 주제가 다룬 부분을 짚는지와 복습 항목 수, 원응답을 직접 읽은 결과다. 자동 채점은 없다.
- 합성 호출만 재생했다. 전체 하네스에서 예산 선택이 동작하는지는 단위 테스트와 빌드로만 확인했다.
